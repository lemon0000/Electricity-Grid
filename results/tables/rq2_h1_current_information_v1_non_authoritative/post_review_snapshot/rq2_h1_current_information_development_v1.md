# Current-only H1 information from an accepted N prefix

R3 DRAFT_NONAUTHORITATIVE. This reader prepares current physical information;
it does not publish a common prefix, select reference/actual dispatch, or grant
execution authority.

The old information chain explicitly assumes an entire normal schedule issued
before the first action. Its allowed-plan identity hashes future forecast rows,
and the old physical carry requires that identity to remain constant. Those
types cannot represent the approved rolling H1 information contract. This
successor constructs none of the old plan declaration, prepared information,
normal-hour view or current-information types. It reuses only pure static
network structures.

`prepare()` requires externally pinned obligation-controller header and last
terminal, plus an exact accepted prefix length. It freshly verifies the full
obligation/source/Job/clock prefix, reconstructs the source parent, and captures
the last packet and accepted child during replay. Exact stage count, projection
identity, request, before, network, lock count and next N boundary are checked
through the existing typed child replay and `_after` path. It rechecks the full
prefix, parent and implementation before returning. A detached ChildInspection,
raw assignment or serialized candidate is not an input to this public API.

The policy-facing `H1CurrentInformation` contains only a fixed H1 rule name,
relative hour, static network, current base demand/bounds/availability/DC limits,
and previous/current normal commitment and current selected generation. Current
conditions are rebuilt from the same H1 packet. Outages remain a separate
disclosure input for a later physical kernel. Its content identity excludes
raw clocks, provenance, solver settings, run records, full N carry and objective
locks. Both the view and its nested values are immutable.

The separate audit envelope binds source timestamp/time basis, packet and
normal request identities, externally pinned controller and child records,
complete N before/after carry, canonical locks and stage count. The audit is
explicitly `policy_visible=false`; it must not be passed to a business policy.
Its 128 KiB bound is a local output limit, not a full resource admission.

The returned immutable view is fresh only at return. Its exact Python type is
not an authentication credential: `detached_consumer_authenticated=false`.
A successor public physical kernel must accept the root and external controller
pins, call `prepare` and consume the view within the same owned operation, then
revalidate the pinned evidence before returning. Accepting a detached decision
or envelope alone requires a separately designed persistent receipt/reader.

Tests distinguish pure synthetic projection examples from a fresh accepted
prefix example. The former check minimal fields, future-row poison, neutral
clock separation and sensitivity to current physical values; they do not
authenticate a normal decision. The latter uses the established explicit
synthetic source/catalog seam and one saved-report Windows Job, then enters the
public reader and tests external-pin and persisted-projection rejection. No
real native solve or real RTS accepted-carry claim follows from these examples.

The next required successors are the H1 physical protocol/carry/kernel,
reference state and selector, actual state and selector, and common publication
and business transaction boundaries. The old fixed-plan exact-type interfaces
remain incompatible. A shared-key conflict journal, full 192-hour coverage,
complete LB/UB evidence, full resource accounting, sealing and independent
official review remain open. Repeated prefix replay is deliberately not claimed
to satisfy the whole-study timing budget.
