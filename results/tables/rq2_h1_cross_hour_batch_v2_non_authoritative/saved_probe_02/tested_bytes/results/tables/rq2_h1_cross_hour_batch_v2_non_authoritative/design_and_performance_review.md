# 跨小时批量历史重放后继

状态：DRAFT_NONAUTHORITATIVE。R3开发，唯一writer为root，独立只读PRE_SEAL复核；不生成production seal、official receipt或运行权限。复用旧connected_06主体、数值和文件证据，原源码及结果保持字节不变。

目的：消除每次owner完整_restore里“对每个已提交小时重复从genesis重建N前缀”的重叠工作。采用**同一次观察内批量重建**：对该次_restore需要的最大已接受N前缀，独立完整重放两遍，保留每个小时的packet/result/after及其外部terminal链；逐小时构造current视图，继续按原phase FSM重放所有Rref/Actual/business记录。观察结束清空批量对象，无跨调用缓存或持久化可信state。

完整DAG：内部source/N0 → owner genesis batch → ready batch → 当小时独立source/Rref/三Actual → intent/原科学transition → 第二次独立source → paired → final batch → 下一小时durable attempt/原normal controller/Job → 同样的current/paired/final → 全close → 新owner两遍历史batch/原FSM → 独立historical与parent snapshot → 全close/保存bytes/报告。

约束：

- 所有requested terminal均由owner binding及保存intent提供，必须属于同一外部pin的obligation predecessor链；不能接收caller提供的frame、carry或证明对象。
- 每次batch都重新检查完整源输入、目录/文件身份、Job/clock、parent/anchor、数值report和registry；两遍共享retained observations只用于发现漂移，不跨观察复用。
- 对每个被选小时只把其packet/after与current registry/source交给原business/selector，批量上下文不进入policy。较后小时的audit信息不能改变较早小时的decision、q/r或carry。
- 批量输出是本次内部重放的数据，不能用作live capability、writer rehydration或跨owner authority。新reader/source/owner有独立implementation identity和新root/header；旧source audit不冒称新实现执行过。
- paired前第二次独立source、普通current的独立source及关闭重开后的完整重放保留。业务数学、数值限、共享预算、非预见性和债务保留原值。
- 原phase FSM逐行保留，由后继提供本次batch的current lookup；全状态转换仍通过原_transition与原数值replay。无skip/fallback或自动重试。

性能假设：连续T个合法active小时、每小时一次run_next、最后一次只读重开，无alternate/pending/no-need额外操作。原owner触发source fresh为T²+5T+2，历史prefix-hour权重4867460（T=192）。后继每个_restore只做两遍最大N prefix，正常current/prepaired仍各两遍；该层prefix-hour权重拟为`4+4T(T+1)`，T=2为28、T=192为148228。它仅是历史prefix这一层的调用量，不是wall估计，也未解决registry、normal controller及科学记录重放的全部成本。必须以实际调用计数核对，不据此启动192h。

优化选择：批量限制在单次_restore，避免引入跨小时可信内存checkpoint及其失效合同。逐小时registry/source仍执行原加载与两次核对；先测量其剩余成本，再决定是否有必要优化。三Actual维持串行，同一current共享、独立carry。测试可复用既有15项pure static identity fixture，但production_overhead_measured仍false。

验收矩阵：新batch各小时的decision、frame、origin/action、exact workload/CFE和scientific payload对原逐小时prepare相同；保存正常/异常数据、pin错位、prefix缺失、source/registry/Job drift拒绝；未来扰动不进入过去policy；owner FSM与原逐小时oracle得到相同科学projection及heads；同一operation与type/creator/capability拒绝路径；两小时三lane仍非零债务/恢复且全close/reopen所有保存bytes一致；原36项适用guard回归。
