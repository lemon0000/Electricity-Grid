# Common registry integration: phase lifetime findings

This addendum refines design204 following independent PRE_SEAL findings from
`/root/public_phase_review_118`. It creates no authoritative review or execution state.

The scientific projection algorithm is preserved, while the physical observation
schedule changes. The current Common report must set `fresh_at_return_only=false`
and declare its held phase dependency reuse. Original Common2 compatibility
payloads may retain their predecessor fields only with explicit compatibility
scope. They cannot describe this call's phase I/O.

The new immutable phase execution observation must be hash-bound inside the
current Common validation report and thus its original Witness execution
receipt's `scientific_payload_sha256`. Record `observation_schedule=common_body_entry_exit`,
`per_call_physical_freshness=false`, `between_bookend_ABA_covered=false`, actual
project/cache-hit counts, the exact phase segment/kernel receipts and current
source/manifest identities. Counts from compatibility reports are projections.

The internal coordinator owns precisely `_prepare_locked`. It binds the actual
body/round/check frames and the five replay ordinals, closes and retires the
last Roster scope, completes phase exit and copies immutable phase observation,
then reconstructs the typed result with current phase metadata and an execution
receipt bound to the final validation bytes. Only afterwards may outer `prepare`
call `_finish_common`. Phase entry/exit or final scope retirement failure poisons
both Bootstrap owner and Witness session and commits no Common row or reusable
proof. Preserve the original body error over every cleanup/reporting secondary.

Before entry, independently verify the bridge's three arm declarations and
canonical roots. Prove controller/Job/clock/source-parent dynamic trees stay
inside the owner's declared study root with no reparse traversal, or declare
the additional exact dynamic roots to the phase operation. The 201 phase byte
comparison is not a proof of that dynamic envelope.

The fixed callback-free source-call inventory includes both rounds, final
manifest and all five Roster replays. Project bound is32: two manifest projects
plus five replays times two views times three candidate projects. Bind the exact
consumer graph and deny added callback, Job/native, durable append or subprocess
routes. Test actual project/check counts and remaining256/4096 limits. Static
data reuse never removes dynamic context or numerical acceptance checks.

Required phase negatives: entry failure, exit failure before `_finish_common`,
final Roster retirement failure, persistent drift before second manifest,
same-code body/round/check clone, callback and trace reentry, dynamic root or
reparse escape, changed source-call inventory and secondary cleanup failure.

Common-wide numerical proof reuse remains a separate design; design204 currently
keeps one numerical registry scope per replay. No new N0 or long chain is launched
while these interfaces and provenance checks remain unsettled.
