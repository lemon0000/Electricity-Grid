# 接回现有功率映射后的主线核验

2026-11-09，DRAFT_NONAUTHORITATIVE。完成用户授权的下一步诊断，不修改冻结模型或论文主张。

## 结论

现有模型的设备容量、仿射功率映射、scalar供电和小时CFE物理上限，能精确压缩为逐小时执行容量。换用不同幅度和不同投运时点不会自动破坏这一性质。恢复债务、期限、事件包络等仍需显式保留；本结论不是完整q/r模型等价于无约束EDF。

因此，前一轮“阶段状态改变接纳边界”机制成立，但暂未找到足以支持新方法主张的不可约物理关系。不能仅以加入待机功率、不同资源进度或CFE约束就声称摆脱标准时变容量调度。

## 解析关系与实际代码核验

令x=w-q+r，a=beta×facility_factor>0，b=facility_factor×idle+aux，则已有power_mapping恰为P=b+a×x。

设备执行约束、供电上限和小时CFE约束共同等价于：

0 ≤ x ≤ min(K, (S-b)/a, (Y/alpha-b)/a)。

alpha=0时省略清洁项；负上界不能截成0，因为待机功耗也可能无法供给。这里Y是1小时步长内可归属清洁电量，不能解释为跨小时储能。

从真实D配置加载8个组合、80小时输入，共720个q/r物理取样点；逐点调用原power_mapping，分别核对原物理不等式与代数边界，全部精确一致。样本不是全部可行调度，业务和事件义务不在该等价式里。

同一8个原full_temporal固定策略轨迹上，59个无调用时段的实际补做量，均等于min(capacity,max_recovery,debt/eta,max(C_t-workload,0))。这只检验实际轨迹的聚合补做量，不证明任意策略或含调用时段等价。原执行与期限评价一并保存。

运行0.158秒，零native求解器，未触及10秒上限。报告读取校验与输入hash核验通过。

## 哪些状态不能抹掉

- 累计调用能量、债务上限、期限分布、事件次数、持续时长、恢复间隔、调用爬坡：不能由只依赖当前外生资源的一个容量数完整替代。
- 这些限制本身已在旧模型中存在；不等价于逐小时容量，并不等于具备研究新颖性。
- grid request与clean request在旧模型按分离请求求和；上述物理约束压缩不能替代两类服务履约约束。

## 机组跨时运行反例与证据限制

两时段单机P∈[0,2]、初始P=0、每小时爬坡≤1。轨迹[0,2]逐小时均不超过2，却违反爬坡；[1,2]和[0,1]均可行。三者证明时段投影的直积不等于连续轨迹可行域。这是已知的跨时约束性质，不是本项目的新定理，也没有真实RTS-24效应量。

源码 `experiments/staged_deliverability_grid_scuc_cost_v1.py` 已有多时段ramp与commitment逻辑；其说明明确case24 RAMP字段为零，所用ramp fraction为mechanism_assumption。当前adapter使用声明scalar limit，也明确不是网络研究。因此不能把本诊断表述为已发现真实网络中的恢复冲突。未运行SCUC。

## 对主线的影响

1. 可以保留阶段履约评价问题。
2. 当前证据不支持以“压缩成容量会失真”描述现有逐时设备/功率/CFE子模型。
3. 若以TSG为目标，需要一个有实证或可靠参数来源的电网—任务联系，且证明标准强基线遗漏了什么；目前尚未具备。仅添加爬坡、储能或随机延期不自动构成贡献。
4. 不建议继续只换标量算例参数寻找算法差距。下一项研究投入应先补业务期限/调度机制与网络动态约束的来源和可观测证据，而非直接运行更大优化。
