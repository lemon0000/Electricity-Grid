# 已排除的优化方向：五次探针的阴性结果

2026-11-08，`DRAFT_NONAUTHORITATIVE`。本文件记录为给论文增加优化维度而做的五次验证，以及它们**全部失败**的原因。目的有两个：防止后续会话重走这些路；作为论文定位取舍的证据。

**结论先行**：在现有标量机制模型族与真实 RTS-24 数据下，没有找到可行、且未被文献占据的优化角度。前四次失败于模型结构，第五次失败于物理数据本身不支持那个机制。

---

## 一、五次探针总表

| # | 设想 | 决策变量 | 结果 | 失败原因 |
|---|---|---|---|---|
| 1 | 标量模型下贪心→最优 | 每小时 q, r | 差距 = 0 | 逾期是物理决定，非策略决定 |
| 2 | 跨小时任务转移（B2） | 任务-小时分配 | 差距 = 0 | EDF 对可分割单资源问题已最优 |
| 3 | 最小接入容量 | 容量缩放 | 判定不变 | 网侧容量不是绑定约束（供电×5 仍不可交付） |
| 4 | 最小业务柔性池（深度） | `flexible_fraction` | 三方法同阈值 | 延期是需求驱动的，超出门槛后增加 f 无效 |
| 5 | 双重承诺「撞车窗口」 | — | 时间不相关 | 电网低谷与风电低谷在 163 小时上独立 |

## 二、逐项记录

### 探针 1：标量模型最优 vs 贪心

**设想**：把 `full_temporal` 的贪心规则换成多时段最优，看可交付判定是否改变。若改变，论文可从"简化方法错了"升级为"即使最优运行该计划也不可交付"。

**结果**：`fast/on_time/early` 单元的逐小时恢复余量：

```
h1  产生 1/5 债务，期限 h3
h2  无请求，物理恢复余量 = 0
h3  期限到，物理恢复余量 = 0
h5  第一个余量 > 0 的小时（1/5），已过期限
```

期限窗口内每个小时的物理恢复余量恒为 0。**任何策略都无法在零余量的小时偿还债务**，所以 1/5 逾期物理上不可避免。

**佐证**：上一会话的判据 A 在 39 个 cohort 上 39/39 成立——逾期完全由"恢复余量在期限窗内是否足够"决定，这是外生物理量。

**脚本**：`experiments/staged_deliverability_greedy_vs_optimal_v1.py`（案例设计失败，缺额远超延期上限，不作有效结果）。

### 探针 2：B2 跨小时任务转移

**设想**：让任务有到达、期限、能量，调度器选择在窗口内哪些小时执行，受逐小时 N-1 容量约束。若最优能救回贪心会逾期的任务，则 B2 有价值。

**结果**：用真实 RTS-24 母线 15 容量剖面（6–728 MW，波动 2 倍）测试：

| 基准负载 | 贪心逾期 | 最优逾期 | 差距 |
|---|---:|---:|---:|
| 200 MW | 91.3 | 91.3 | 0 |
| 300 MW | 182.9 | 182.9 | 0 |
| 400 MW | 576.6 | 576.6 | 0 |
| 500 MW | 707.8 | 707.8 | 0 |

另用四种专门制造差距的任务结构（competing、valley-straddle、tight-vs-slack、forced-harmful-EDF）测试，差距仍全为零。

**原因（理论）**：单资源、任务可分割、线性目标的调度问题，**最早期限优先 + 贪心填充本身可证明最优**（经典调度理论）。逾期只在两种情形发生——任务窗口落在容量谷，或窗口内总容量不够——都是物理不可行，最优调度不能凭空创造容量。

**打破 EDF 最优的前提**：需要不可分割任务、启动成本、或注入点耦合。这些是实质性新模型，且仍可能因真实容量谷太深而退化。

**脚本**：`experiments/b2_shifting_probe_v1.py`。

### 探针 3：最小接入容量

**设想**：既然优化运行无效，优化容量——求使计划可交付的最小接入容量。

**结果**：把供电放大 5 倍，`full_temporal` 仍判不可交付。

```
supply ×1   inst=True  fixed=True  full=False
supply ×5   inst=True  fixed=True  full=False
```

**原因**：瓶颈不在网侧供电容量。恢复余量公式 `min(capacity, max_recovery, debt/eta, compute−workload, (supply−ref)/slope, …)` 中，到期窗口内绑定的不是供电项。

### 探针 4：最小业务柔性池

**设想**：把 `flexible_fraction`（可延期计算占总负荷的比例）作为规划决策变量，求三种评价方法各自判可交付的最小柔性池。若不同，简化评价低估柔性需求。

**结果（10 小时 D fixture）**：只要某方法能判可交付，最小 f 都是 2/5。完整时序在 3 个单元里 f 加到 1 也判不可交付。

**根本原因（关键诊断）**：

```
f=2/5  deferred=1/5  recovery=1/5
f=1/2  deferred=1/5  recovery=1/5
f=3/5  deferred=1/5  recovery=1/5
f=4/5  deferred=1/5  recovery=1/5
f=1    deferred=1/5  recovery=1/5
```

不管 f 多高，**总延期量恒为 1/5**。因为模型只延期"不得不延的部分"，从不延期"可以延但不必延的部分"。`flexible_fraction` 只是上限，实际延期量由缺口决定。

**这是探针 1–4 的共同根因**：当前标量模型里延期是**需求驱动**的（服务不了才延），没有**机会驱动**的（延期本身带来收益）。没有收益项，柔性池大小就无关。

**升级版（三阶段错位，22 小时窗口）**：六种错位形态（aligned / grid_late / equip_late / both_late / clean_early_only / clean_late_only）全部同类结果——要么同阈值，要么 f 取任何值都不可交付。

**脚本**：`experiments/min_flexibility_probe_v1.py`、`experiments/three_stage_flexibility_probe_v1.py`。记录：`docs/plan/min_flexibility_probe_v1.md`。

### 探针 5：双重承诺的「撞车窗口」

**设想**：仓库冻结的 70-cell 相图报告 `R1=0, R2=0, R3=69, mixed=1`——所有 cell 都是"共同不足"，没有一格是"双重承诺"。若能把 R2 的窄带刻画出来，论文可问"在什么条件下双重承诺才成立"。进一步假设：双重承诺风险集中在**电网事件与 CFE 缺口时间相遇**的小时。

**第一步（成功）**：手工构造窄带，验证分类器能否识别。

| 用例 | 电网 | CFE | 电网单独 | CFE 单独 | 联合 | 判定 |
|---|---:|---:|---|---|---|---|
| 窄带：各自都够 | 0.9 | 0.9 | 可解 | 可解 | 不可解 | **R2** |
| 窄带：不对称 | 0.8 | 0.5 | 可解 | 可解 | 不可解 | **R2** |
| 无冲突 | 0 | 0 | 可解 | 可解 | 可解 | R1 |
| 电网单独就超 | 1.6 | 0.1 | 不可解 | 可解 | 不可解 | R3 |
| CFE 单独就超 | 0.1 | 1.6 | 可解 | 不可解 | 不可解 | R3 |
| 边界：grid 正好等于池 | 1.0 | 0.1 | 可解 | 可解 | 不可解 | R2 |
| 边界：两者之和正好等于池 | 0.6 | 0.4 | 可解 | 可解 | 可解 | R1 |

8/8 符合定义，含两个边界用例。**分类器是精确的**，冻结的 `R2=0` 是数据性质而非模型缺陷。

**第二步（失败）**：检验「撞车窗口」假设。用阶段 1 的真实 N-1 容量与 RTS-24 母线 `122_WIND_1` 的真实风电出力，163 小时，四种阈值：

| 阈值 | 容量低谷小时 | 风电低谷小时 | 同时 | 独立期望 | 比值 |
|---|---:|---:|---:|---:|---:|
| 最低 20% | 32 | 32 | **7** | 6.3 | 1.11 |
| 最低 25% | 40 | 40 | **11** | 9.8 | 1.12 |
| 最低 30% | 50 | 48 | **15** | 14.7 | 1.02 |
| 最低 50% | 81 | 81 | **37** | 40.3 | 0.92 |

**四个阈值的比值都在 0.92–1.12，即独立时的值。电网容量低谷与风电低谷在时间上不相关。**

**原因**：电网 N-1 容量低谷由系统负荷高峰驱动；风电低谷由天气驱动。两者没有共同的驱动因素。

**一次附带错误（记录以备追溯）**：尝试用"约束激活"口径重做时，把 `case_load_mw`（系统总负荷，2850 MW 量级）与 `n1_min_mw`（POI 单点转移能力，394–811 MW 量级）直接比较，导致 `grid_active` 100% 触发，规则失效。两者量纲不同，不能直接比。

**脚本**：`experiments/r2_narrow_band_probe_v1.py`。

## 三、文献核查（同期完成）

三篇候选最近邻已下载全文（`docs/literature/arxiv_three_papers_20261108/`）并核对：

| 文献 | 做了什么 | 是否占了我们的方向 |
|---|---|---|
| 2609.38020 Batch Workload Temporal Shifting | 评估柔性上限（削峰量、可持续削减时长），延迟约束 + 服务器容量 | 是：柔性评估维度 |
| 2608.19622 Shift or curtail? | 柔性分类嵌入容量扩展（PJM/Korea），事件形状约束（深度/时长/爬坡/恢复） | 是：柔性价值与恢复约束 |
| 1109.3839 Dynamic Deferral (2011) | SLA 期限下最小化能耗，offline LP + 在线算法 | 是：期限 + 延期 + LP 规划 |

**三篇共同点**：都假设柔性配置给定，都做单阶段或年度规划，都**没有**在分阶段达产的时序错位下把柔性池大小作为规划决策变量，都**没有**多种评价方法对照。

**因此不可作为新颖性主张**：延时时长、恢复约束、SLA 期限调度、柔性上限评估、最小接入容量（DC22）。

## 四、为什么五次都失败：结构性原因

前四次共享同一个根因，第五次是另一个：

**根因一（探针 1–4）：模型里没有延期的收益项。**

当前 `advance()` 是规则而非优化：能服务就服务，服务不了才延期。延期量因此被缺口钉死，任何"柔性上限"类的决策变量都无效。要让柔性池成为有意义的变量，必须引入延期带来的收益（削峰、降需量电费、提高 CFE 匹配率）——但这正是 2609.38020 / 2608.19622 已占的地盘。

**根因二（探针 5）：两个约束的驱动因素不同。**

电网容量低谷由负荷驱动，风电低谷由天气驱动。它们在时间上独立，所以"撞车窗口"不是集中现象。

## 五、留下的可主张内容

五次失败之后，仍然站得住的是**结构性结论**，不是优化方法：

1. **判据 A（恢复窗口）**：任务 $j$ 的可用恢复余量在 $[a_j,d_j]$ 内累计不足其延期工作量 → 必逾期。验证 39/39。
2. **判据 B（余量越界）**：方法自身发出的恢复指令超过该小时物理可用余量 → 重放必报 `recovery_headroom`。验证 39/39（限实际执行到的小时）。
3. **逾期是物理决定，非策略决定**：贪心与最优给出相同判定。
4. **真实 N-1 容量**：阶段 0/1 算出的逐小时可交付容量，选址效应约 6 倍。
5. **双重承诺分类器是精确的**，`R2=0` 是数据性质，不是模型缺陷。

**这些支撑的定位**：可交付性失效是计划-网络的结构性质，简化评价系统性误判它，运行/柔性优化无法补救。这是方法论贡献，适合 TPWRS 方法类或 Applied Energy；投 TSG 的优化赛道风险高。
