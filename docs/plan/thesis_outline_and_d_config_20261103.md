# 第一部分：论文骨架

## 0. 定位一句话

面向一个固定接入点的 AI 智算中心，在业务达产、设备分批投运与电网扩建三条给定进度路径下，建立一个逐小时的可交付性判据，用三种评价方法（瞬时可调 MW、固定恢复余量、完整时序）对同一计划分别定值，并识别三种方法产生不同判断的阶段与条件。

目标体裁：IEEE 一区 Trans（TSG/TSTE）。体裁决定写法——这是 **assessment framework + case study**，不是 optimization paper。全文不得出现"最优""经济性""应投资"一类措辞。

## 3. 判断差异标签（6.3 的表格口径）

每个"计划 × 情景 × 阶段"对三种方法各得两个定值：方法自身定值、该方法的安排在完整时序约束下的重放定值。由此产生：

| 标签 | 含义 | 论文用途 |
|---|---|---|
| D1 假通过 | 方法判可交付，重放判不可交付 | **最有价值**：说明工程惯例会放过会违约的计划 |
| D2 假拒绝 | 方法判不可交付，重放判可交付 | 说明简化检查过度保守，损失可接入容量 |
| D3 一致通过 | 两者皆可交付 | 简化评价足够成立的范围 |
| D4 一致失败 | 两者皆不可交付 | 一致范围 |
| D5 未决 | 任一为未决 | 单列，**不计入 D1–D4** |

正文必须报告 D3/D4 与 D5 的占比，不能只报告 D1/D2——这是审稿人判断"是否在挑选有利结果"的最直接检查点。

## 4. 必须在正文显式出现的边界（避免被拒的关键）

1. 单一 POI、少量给定计划 → 结论限定于声明范围，不谈普适性。
2. 网络结论限于 selected-N-1 DC 与声明故障集合；`security_certified=false`。
3. AC 侧有既有负证据（direct replay 2296 收敛、0 direct-secure），须作为"本文不做 AC 认证"的依据明写，不可省略。
4. 跨源配对（工作负载 / 可再生 / 网络）是构造情景，不解释为同址同钟观测。
5. 不宣称：最优 F/X、投资时序、经验违约概率、工程可行性。
6. 既有负结果必须带入：70-cell 相图退化 `R1=0,R2=0,R3=69,mixed=1`；两版 H2 跨来源消融均为阴性；1900 单元中 1856 个被单小时必要条件排除。这些是"本文的设计选择为何如此"的证据，不是可隐藏的失败。

# 第二部分：D 的最小可行配置

## 6. 为什么 D 可以立即启动

B1/B2/B3 三条已跑通的链都是**零 solver 调用**的评估链：B1 为 180 策略步 + 180 独立审计步（脚本 3.007 s）；B2 为 52 网络小时 / 50 业务步 / 362 个 PYPOWER 点（12.327 s，RSS 268 MiB）；B3 为 599 点 / 84 提案 / 86 网络尝试（15.321 s，270 MiB）。D 只复用这三层机制，不新增求解器。

因此 D 属于 `agent.md` §9 意义上的**有界诊断/机制比较**，不是长运行、不是 formal run：可按 §9 登记预算后开展，不需要 formal-run authority。这一点与 F 链有本质区别——F 每推一步都要重新核资源与授权。

## 7. 算例网格

| 维度 | 水平 | 取值来源 |
|---|---|---|
| POI | 1 个 | B2/B3 已固定的两母线 + RTS-24 |
| 给定计划 | 3 个（基线 / 电网加速 / 电网延期） | 构造，声明的情景假设 |
| 业务进度 | 快 / 慢 达产 | 2 水平 |
| 设备路径 | 单独给定，含安装/在建/可用三态 | B1 已有的状态机 |
| 窗口 | 16 小时（含 2 次阶段切换 + 已登记期限 + 必要后续观察） | 由 B1 的 10 小时扩展；理由是至少要覆盖一次切换后到期限的完整恢复 |

主网格 = 3 计划 × 2 业务进度 = **6 个阶段单元**，每单元 3 方法 × 2 定值 = 6 次评估 → **36 次评估**。

恢复时段匹配臂：同样 6 单元 × 3 个到达时段 × 2 定值 = **36 次评估**。匹配约束按介绍 §3 第 2 项：固定即时网侧与 CFE 请求、已兑现延期、恢复起点债务、清洁额度总量与峰值，只改到达时段。

敏感性（必要最小集）：可延期比例 f ∈ {5%, 20%, 50%}（依据 10-21 核查的三个临界点）、设备余量 K 两水平、CFE 目标 α 三水平。敏感性分支只跑 6.3 的 D1/D2 判定，不做全量重放，以控制成本。

**目标网格选取原则**：D1/D2 最可能出现在"恢复额度到达窗口刚好卡在期限前后"与"K 余量接近业务占用"的交叉处（10-21 的 K=0.3/0.4 对照即此）。网格必须覆盖该侧，不能用均匀网格。

## 8. 成本估计（登记用，非实测）

按 B2/B3 的实测比例外推，每 16 小时单元的 PYPOWER 点量约 580；36 × 580 ≈ 21k 点，按 B3 的每点约 25–40 ms 计，主网格 PYPOWER 时间约 9–14 分钟，加上审计与持久化，**主网格 wall 约 0.5–1.5 小时**；匹配臂同量级；敏感性约主网格的 1/3。

**总预算登记：wall ≤ 4 小时，RAM ≤ 512 MiB/进程，产物 ≤ 32 MiB**，无 solver 调用、无外部下载、无付费查询。

三项不确定性必须写明并进 §9 审查：(a) 16 小时窗口的恢复链可能触发 B3 已登记的 O(T²) 状态编码访问，小例不能外推；(b) RTS-24 逐点成本高于两母线，若主网格改用 RTS-24 需重新估；(c) 敏感性分支的判定复用可能引入依赖耦合，须在登记时就固定。

## 9. 停止与失败处置

- 任一单元出现求解未决或数值异常 → 记 D5，单列，**不重跑追平**。
- wall 或 RAM 触及登记帽 → 停止，保留已接受单元，不延期续跑。
- 若主网格出现 D1/D2 全为零：先核对网格是否覆盖了 §7 的临界侧，再考虑扩大网格；**不得**在看到结果后调整标签定义或收缩报告范围。
- 所有 attempt 保留原字节，失败不删除、不覆盖。
