## 0. 为什么需要 E

D 与敏感性都在**同一 10 小时 fixture 骨架**上变化参数：`first_hour=-2`、`last_hour=7`、设备路径、电网工期、清洁路径形状全部沿用 B1 冻结值，敏感性只动 f / K / α 三轴。审查方可以合理质疑：假通过是这套 fixture 的产物，而不是简化评价的一般性质。

E 回答一个问题：**在 D 从未见过的外生路径上，冻结的计划、设备、策略与三种评价方法，是否仍产生同类分歧？** 它不新增方法、不改判据、不重新选择参数。

## 2. 留出路径（执行前固定）

四条留出维度的水平由下述规则机械生成，不读取任何 E 结果：

1. **清洁路径**：D 只用 `early`/`late`，二者总量同为 `317/50`、峰值同为 `26/25`，仅在 h2/h4 互换。E 的窗口延长到 h9，故 E 的两条留出路径以**彼此**匹配为约束（总量与峰值相同），而非与 D 相同——窗口长度不同，按小时额度不可直接对齐。

   **可行性约束（2026-11-06 更正）**：达产后 `alpha × reference = 4/5 × 21/20 = 21/25`，因此达产小时段（h2–h9，与 `change_hour` 无关地按 workload 取上界计）的清洁额度**不得低于 21/25**，否则 `hourly_cfe` 无条件触发，三种方法一起失败，留出退化。D 的路径正是按此构造：达产时段全为 `.84`，仅一小时抬到 `1.04` 提供恢复余量。E 沿用该结构，只移动抬高的那一小时：
   - `holdout_a`（清洁后置）：`[.60,.50,.84,.84,.84,.84,.84,.84,1.04,.84]`，抬高在 h8
   - `holdout_b`（清洁前置）：`[.60,.50,1.04,.84,.84,.84,.84,.84,.84,.84]`，抬高在 h2
   - 二者总量均为 `401/50`，峰值均为 `26/25`；h0/h1 与 D 相同（保持低清洁小时的结构性约束）。

   **attempt_02 作废说明**：初版留出路径把达产时段的清洁额度设为 `.60/.64`，低于 `21/25`，导致 8 个单元中 7 个全 D4、1 个 D1，属可行区外退化，不构成留出证据。该 attempt 保留不删，作为"设计错误"的记录。
2. **业务达产时点**：取 `change_hour = 1` 与 `change_hour = 4`（D 为 2/3/5）。
3. **窗口**：`first_hour = -2` 不变，`last_hour = 9`（D 为 7），使期限与全部恢复事件落在窗口内；`deadline_lag = 2` 保持。
4. **电网延迟**：取 `delay = 1` 与 `delay = 3`（D 为 `{on_time: 0, delayed: 2}`），两个水平都不在 D 中出现。

**这些水平必须是外生可确定的**，不能是"跑完看哪组好看"。规则写定后即冻结。

## 5. 成本登记（§9 审查前）

按 attempt_01 实测 24 次评估 1.12 秒、attempt_05 648 次评估 5.31 秒，单次评估约 8–47 ms。E 为 36 次评估，预期 CPU 时间 < 2 秒；加装载、审计与持久化，wall < 60 秒。

**登记上限**：wall ≤ 600 秒；单进程 RSS ≤ 512 MiB；产物 ≤ 8 MiB；并发 = 1；零 solver 调用、零外部下载、零付费查询。

**§9 六项覆盖状态**：

| §9 项 | E 的覆盖 |
|---|---|
| 1 完整路径与调用量 | 装载 → 36 单元 × (方法执行 + 重放 + 参照执行) → 汇总 → 持久化；无递归、无回调、无历史重放 |
| 2 整体优化空间 | 无可复用计算；单进程顺序执行已是最简路径；不引入缓存 |
| 3 有界代表性实测 | attempt_01/05 已提供同链实测；E 与二者共享全部执行阶段，仅网格更小 |
| 4 科学与校验等价 | 方法与判据冻结；测试 E1/E2/E3 为新增校验 |
| 5 预算与停止条件 | 见上；超限即停，保留已接受单元 |
| 6 绑定与结论 | 报告钉住 fixture、代码与依赖的 SHA-256 |

§9 审查**已闭合**：E 的执行路径是 attempt_01/05 的子集，实测证据可直接复用，无需新的性能探针。
