# 智算中心分阶段接入与小时级绿电协同规划：科研项目执行步骤

## 一、项目最终要回答什么

本项目只围绕三个研究问题展开：

1. 当数据中心达产和电网扩建进度逐步揭示时，多阶段自适应接入相对静态接入和两阶段规划有多大价值？
2. 同一业务灵活性如果同时被用于网络条件削减和小时级绿电匹配，会高估多少条件容量并产生多大履约风险？
3. 年度绿电匹配与小时级清洁电力匹配会不会产生不同的接入容量、扩建时序和业务调度决策？

项目的主创新是多阶段自适应F/X容量释放，第二创新是网络服务与绿电匹配共享灵活性预算。恢复债务、CVaR、N-1和代表周属于支撑模型，不分别包装为创新。

## 五、第四步：复现基础电网并完成确定性MVP

不要一开始加入随机规划和绿电。先保证最基本的网络模型可信。

### 依次实现

1. 导入RTS-24并复现基础DC潮流或DC-OPF；
2. 检查节点功率平衡和线路潮流；
3. 建立关键N-1故障潮流；
4. 加入候选线路或主变扩建；
5. 加入一个固定节点、固定规模的数据中心；
6. 设置确定性的季度达产路径；
7. 让模型选择是否扩建以及何时扩建。

### 必须通过的测试

- 数据中心负荷为零时，结果回到基础系统；
- 网络容量无限时，不发生网络削减；
- 扩建成本极低时，模型倾向提前扩建；
- 扩建成本极高时，模型不会无条件建设；
- 候选工程只有在工期结束后才能提供容量；
- 所有关键N-1状态均无热越限；
- DC最优方案能够通过AC潮流事后检查，或能解释偏差来源。

### 产出

- 基础潮流表；
- N-1越限表；
- 候选扩建结果；
- 一个可重复运行的确定性MVP。

## 六、第五步：加入分阶段F/X接入机制

### 实现内容

- 定义保供容量F；
- 定义条件容量X；
- 删除独立的U容量变量；
- 扩建完成后，通过接入点容量上限允许后续F/X增加；
- 定义条件容量调用的触发、持续时间、事件次数和能量预算；
- 定义首个可运营容量块B_min；
- 计算T20、T50和T100。

### 首先完成三种基线

1. 等待全部扩建完成后一次性接入；
2. 按确定性达产曲线分阶段接入；
3. 静态F/X接入，不允许根据后续信息调整。

### 必须检查

- F在规定N-1集合下不因网络拥塞削减；
- X只能在约定条件内调用；
- 实际服务功率、合同削减和非合同服务缺口严格区分；
- T20不能由1 MW或其他无运营意义的容量触发；
- unused MW-year只作为物理指标，不随意货币化。

## 七、第六步：加入场景树和多阶段适应性

### 先从小场景树开始

初始场景只需要覆盖：

- 正常达产；
- 延迟达产；
- 加速达产；
- 工程按期；
- 工程延期；
- 加速达产与工程延期联合压力。

不要一开始为每个季度建立大量分叉。先用少量决策节点验证信息结构，再逐步增加复杂度。

### 依次建立

1. 确定性分阶段模型；
2. 两阶段随机模型；
3. 多阶段随机模型；
4. 完美信息模型，作为理论下界。

### 核心检查

- 相同历史节点的F/X和扩建决策完全一致；
- 单一确定场景下，两阶段与多阶段结果一致；
- 多阶段模型只能利用当前已经揭示的信息；
- VMA在相同外样本和相同安全标准下计算；
- 如果VMA接近零，应作为有效结果，而不是修改参数直到得到正结果。

## 八、第七步：加入完整业务灵活性包络

### 负荷拆分

- 刚性业务：关键推理、网络、存储和必要基础设施；
- 柔性业务：可暂停、延迟或降频的训练及非关键任务；
- 非恢复损失：被放弃而不是延期完成的业务，单独计量。

### 加入约束

- 可削减MW；
- 最大连续削减时间；
- 最大事件次数；
- 事件间最小恢复时间；
- 累计削减能量；
- 恢复债务；
- 恢复功率上限；
- 期末债务边界。

### 时间样本要求

必须使用连续代表周或连续压力窗口。无链接代表日不能用于证明最大持续时间、事件次数和日际恢复债务可行。

### 对照实验

- MW-only灵活性模型；
- 完整持续时间模型；
- 完整持续时间+事件次数+恢复债务模型。

比较它们对X、业务违约和恢复峰值的影响。

## 九、第八步：加入年度和小时级绿电

### 先做年度匹配

约束年度可归属清洁电量达到数据中心年度用电量的一定比例，验证基本能量平衡。

### 再做小时级匹配

要求每个小时的可归属清洁电量达到该小时数据中心用电量的目标比例，同时满足网络潮流和新能源可用出力。

### 绿电建模边界

- `y_CFE`表示同小时可归属清洁电量；
- 不声称追踪电子的物理来源；
- 网络模型证明清洁注入和数据中心取电能够同时实现；
- MVP不加入储能属性追踪和绿证交易；
- 绿电缺口与电网服务缺口分开统计。

### 最关键的统一预算

网络条件削减与绿电移峰必须共享同一个柔性负荷上限：

```text
c_grid + c_green <= D_flex
```

同一工作负载不能同时被承诺给两类服务。

### 必做对照

- 无绿电目标；
- 年度绿电匹配；
- 小时级CFE匹配；
- 允许灵活性重复承诺；
- 禁止灵活性重复承诺。

## 十、第九步：完成三条核心证据链

### 证据链A：多阶段适应性价值

比较等待扩建、确定性分阶段、静态F/X、两阶段、多阶段和完美信息模型。

回答：多阶段方案在什么条件下有价值，在什么条件下没有价值？

### 证据链B：灵活性重复承诺风险

比较允许重复承诺和统一预算模型。

回答：错误建模会高估多少X，并产生多大的场景外履约失败和恢复债务？

### 证据链C：绿电时间粒度

比较无绿电、年度匹配和小时级CFE。

回答：小时级目标是否真正改变容量释放和扩建，还是只增加成本？

每条证据链都必须对应一个RQ，避免出现大量结果却无法支撑核心结论。

## 十一、第十步：进行场景外验证和规模扩展

### 场景外验证

使用与训练场景独立的需求达产、工程延期和新能源路径执行已经得到的策略。

场景外评估时不能重新使用完整未来信息优化，否则会把策略执行误写成完美预见。

报告：

- 指标均值和分位数；
- CVaR；
- 置信区间；
- 履约失败概率；
- 极端联合情景；
- 参数错设和分布外压力测试。

### 规模扩展

确定性MVP和核心机制稳定后，再迁移到RTS-GMLC：

- 扫描多个候选POI；
- 区分局部主变、输电走廊和系统性瓶颈；
- 使用多个候选扩建项目；
- 进行关键N-1筛选；
- 对代表性最优方案进行AC复核。

不要把“从24节点换到118节点”直接当成泛化验证。更重要的是多POI、多瓶颈类型和场景外稳定性。

## 十三、第十二步：按证据写论文

推荐写作顺序：

1. 先写Problem Setting和数学模型；
2. 再写数据、场景和实验设置；
3. 再写结果；

论文贡献保持三条：

1. 多阶段F/X接入与扩建决策；
2. 网络服务与小时级CFE共享灵活性预算；
3. 多POI和场景外验证得到的适用边界。

Discussion必须说明：

- F/X在不同制度下的可能映射；
- 合成数据的局限；
- DC潮流和代表周的局限；
- 未纳入储能、市场和电价的原因；
- 哪些结论是结构性的，哪些只适用于测试系统。

## 十四、项目全过程的停止规则

出现以下情况时不要继续叠加新模块：

- 基础潮流和N-1尚未验证，就开始多阶段模型；
- 非预见性尚未通过测试，就加入小时级绿电；
- 恢复债务依赖无链接代表日；
- 只有人为调高拥塞或延期时方法才有优势；
- 结果完全由任意货币权重决定；
- 绿电只增加成本，从不改变接入、扩建或灵活性分配；
- 多阶段、重复承诺和小时CFE三条证据链均无辨识度。

遇到这些问题，应先缩小模型、修正规格或降低论文主张，而不是增加强化学习、储能市场、复杂博弈或更多优化算法。
