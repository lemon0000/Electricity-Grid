## 结论

研究问题的机制成立，但当前模型没有显示新的算法贡献。阶段容量和债务期限改变接纳边界；完整阶段信息上的标准 EDF 在全部1188个场景—尺度组合上与精确最大流一致。不能把弱静态基线差异包装成胜过现有调度方法。

## 运行与核验

36场景×33尺度；3564次纯Python最大流，1188次EDF；每个最大流用15个非空任务子集的Hall容量条件独立核验。另有5个解析测试，含共享恢复窗口争用、到期边界、紧迫与宽松任务竞争。0.778秒完成；Python跟踪分配峰值4,844,161字节（不是进程RSS）；报告5,419,955字节。无native求解器调用。任务余额、窗口、容量及全部参考一致性断言通过，输入与脚本hash运行前后相同。

## 可复核现象

以下数值为每批新增任务的归一化工作量lambda，三批均取相同lambda；不是MW。资源当前余量均为2，最终均为4，继承债务均为1。

|设备/电网/清洁余量升级时点|债务期限|精确接纳边界|
|---|---|---|
|h1 / h1 / h1|h1|25/3 ≈ 8.333|
|h1 / h3 / h1|h1|5|
|h1 / h3 / h1|h5|6|
|h1 / h1 / h5|h1|9/2 = 4.5|
|h1 / h1 / h5|h5|5|

同一资源路径、同一当前余量、同一总债务，将其期限由h1变为h5可使边界5→6；故总债务一个标量不足以描述接纳能力。新增lambda=5.5时，前者不可行而后者可行；这里任务截止时间分布是预设状态差异，不是通过延长同一任务SLA来改善方案。

保持所有任务完全相同，电网从h3改为h1升级，边界5→25/3；lambda=6时前者不可行、后者可行。此为候选计划的可接纳决策差异，不是有成本依据的最优建设计划。

## 扫描上限与解析补充

原扫描到lambda=8，terminal_frozen全部与chronological两项右端未闭合；原report中的boundary仅是扫描最大通过值。不得引用8为连续最优值。

本独立可分割模型可由全部任务子集约束求出连续边界：对任一包含新任务的子集J，lambda不超过“该子集允许小时并集的总容量减继承任务量”除以新任务数。容量原始量以四分之一单位记录，解析公式相应除4。对全部子集取最小即得到此二部流模型的充要条件。该结论来自经典最大流/Hall结构，不是新定理。

## 不能外推的边界

- 设备、电网、清洁三类容量均使用同幅单阶跃，实际余量为三者最小值，18个资源计划退化为3条容量路径。36场景不是36种独立机制，不支持复杂三方交互的主张。
- 继承债务视为当前给定状态；未构造其前史可达性，也未证明真实业务下状态发生概率。
- 独立任务模型允许可分割任务在窗口内执行；不包含旧q/r模型的事件包络、调用与补做互斥、效率、CFE计量、电网潮流或设备待机映射。
- 固定已知容量路径，未验证未知延期下的鲁棒承诺、实际网络接入或成本最优。
- 本次不支持TSG贡献已成立；先识别真实存在且不能被标准时变容量调度吸收的电网—业务联系，再决定是否扩展模型。不得为了产生差距添加任意复杂性。
