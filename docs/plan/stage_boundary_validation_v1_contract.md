# 阶段接入边界主线验证：运行前契约

2026-11-09；用户授权“可以 验证吧”。DRAFT_NONAUTHORITATIVE，有界机制诊断，不启动正式实验、不改旧模型或结果。

## 问题与判别标准

A：同一当前余量与即时指标，未来设备/网侧/清洁进度或债务期限是否改变接纳边界？
B：边界是否改变允许新接纳的负荷尺度？
C：保留全部阶段容量和任务期限的标准 EDF 是否已与精确参考一致？若一致，必须报告当前模型没有显示新增算法价值，不能用弱基线差异宣称新方法。

## 独立简化模型与固定设计

这是独立可分割单资源任务模型，**不声称等价于现有 q/r 模型**。时间为 h0..7，每步1h。所有量为归一化工作单位，4整数单位对应1单位工作量；容量为归一化工作/小时，不能直接报告为真实 MW。

各小时可执行能力是设备、网侧和清洁恢复等效余量的最小值；三者已经扣除外生刚性负荷。它们是明确的合成机制假设，不是 RTS-24 网络计算。设备、电网各在 h1/3/5 从2升到4；清洁等效资源在h1或5从2升到4，当前h0均为2；18种资源计划。继承债务工作量为1，分别在h1或h5到期，两种状态总债务相同。共36场景。

新业务形状固定：h0/2/4分别到达一批，工作量均为lambda，期限分别为h2/4/6（含到期小时）。lambda是候选接纳规模，不是允许已经接纳业务被丢弃；相同lambda跨方法对应完全相同任务。lambda扫描0..8，步长1/4，33点；所有到期小时处于观察窗内，禁止截断期限。

对照：当前容量冻结、最终容量提前可用、真实时变容量；三者使用相同任务期限与精确最大流。另用真实时变容量上的工作守恒EDF。离线已知容量假设对各方法一致；EDF虽不看未来，不据此声称不确定性下的在线保证。

精确参考：source→job(工作量)→hour(仅允许到达至原期限)→sink(每小时容量)整数最大流。独立参考：枚举全部非空任务子集，检查需求是否超过可用小时并集容量（该可分割二部流模型的Hall条件）。最大流返回安排逐项检查任务余额、时间窗、容量和整数值。EDF独立实现按小时执行已到达任务。

## 预算与产物

DAG：构造36场景→33尺度×3最大流（3564次纯Python小图，非native solver）及1188次EDF→每个最大流结果15个任务子集检查→边界汇总→JSON/SHA→重读。最多4任务、8小时、14节点；不下载、不付费、不调用建模器或native solver。

每个输入构造一次，复用容量与任务模板；不重复解析YAML。串行，60s wall硬停止（每场景尺度检查），输出10MiB硬检查；记录实际总耗时、Python内存峰值、代码/本契约hash。失败保存已完成场景与异常，禁止覆盖结果。新增普通测试含共享窗口争用反例与期限边界。独立只读开发审查，不打开任何正式gate。

该包本身是有界性能/机制诊断，无法用于大型实验准入。首个与全部场景耗时保留；资源规模确定后不增加扫描。解释边界：只有扫描分辨率下的接纳区间，不能声称连续最优值、成本收益、真实接入认证或新颖性。
