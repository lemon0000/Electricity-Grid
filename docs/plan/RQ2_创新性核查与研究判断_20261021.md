# 智算中心柔性可交付性的证据核查与研究判断

2026年10月21日。探索性研究判断。

> 2026-10-22研究设计衔接：当前[项目介绍](../../paper/drafts/README.md)以达产与建设进度错位为背景，评价少量给定分阶段接入计划；阶段性K、任务恢复及小时CFE进入同一履约检查。该阶段模型衔接尚待实施。下文小模型与原始排除证据仍按10月21日的含义解释，其中联合投资与自适应开工建议属于进一步研究，不构成当前主实验已完成或必须实施的内容。

当前证据显示两个不同的问题。现有参数设计中的大部分单元，在单个小时就因可延期任务份额不足而被排除；这还没有检验跨小时恢复的作用。另一方面，一组精确可核查的小例子表明，在相同调用和清洁电量总额下，恢复额度的到达时刻确实可以改变容量需求。下一步应先明确清洁电额度与业务能力的依据，再检验这种时序约束是否会改变分期投产决策。

## 现有1,900个单元被什么条件排除

本次从绑定的原始CSV重建两条完整168小时训练窗口，独立复算全部1,900个单元的算术及身份，重现1,856个CFE相关规划单元的排除记录。这是对任何假设完整服务轨迹的局部必要条件；未证明选中配对的normal/reference运行可达性，也不是逐配对执行失败或已计算的training UB。其余44个单元只是未被这个证人排除，并不代表可行；network-only的1,900个单元仍未判定。

这些排除均来自同一个登记小时：电力源小时354与工作负荷源小时570，在声明的配对窗口内都对应相对小时162。投影负荷w约为0.8155；方案A由源输入派生的清洁份额R约为2.37%。这里的R是模型派生值，不是具名数据中心的实测清洁电力供应。

按照当前规则，清洁额度为R*w。若最多只能推迟f份额的任务，则即使把这些任务全部移走，剩余当期用电仍至少为(1-f)*w。忽略极小的活动阈值，可以得到直观必要条件：

**小时级CFE目标alpha不能超过R/(1-f)。**

| 可延期比例f | 该小时的简化目标上限 | 当前1个百分点网格中未被该证人排除的目标 |
|---|---:|---|
| 5% | 约2.50% | 1%、2% |
| 20% | 约2.96% | 1%、2% |
| 50% | 约4.74% | 1%、2%、3%、4% |

程序实际保留原活动阈值及两个tau的局部放松量，使用有理数逐项重算，没有用简化上限代替证明。19组任务参数中的全部计数均与原记录一致。

**这部分证据说明的是当前资源设定的瞬时边界。** 增加调节容量、延长求解时间或改进恢复策略，都不能把不可延期业务变成可延期任务。它没有证明所有实际项目都无法满足较高CFE目标，也不提供失败率、真实联合分布或正式容量前沿。原有单元和负结果全部保留。

## 恢复时序能否产生独立于瞬时调用的影响

构造6个小时的小例子，每小时基准负荷为0.2；h0承担0.1的网侧调用，h1承担0.1的CFE调用。两份被推迟的工作各为0.1，效率先取1，分别须在h3、h4恢复完成。两类调用不同时发生。

下面两个情形具有相同的调用序列、业务总量、清洁份额边际、清洁额度总量和峰值。每个有额度的恢复小时最多支持0.2，其他小时为零。

| 小时 | h0 | h1 | h2 | h3 | h4 | h5 |
|---|---:|---:|---:|---:|---:|---:|
| 固定调用量 | 0.1 | 0.1 | 0 | 0 | 0 | 0 |
| 情形A可用清洁恢复额度 | 0 | 0 | 0.2 | 0.2 | 0 | 0 |
| 情形B可用清洁恢复额度 | 0 | 0 | 0 | 0.2 | 0 | 0.2 |

情形A可以在h2、h3各恢复0.1，最低双向调节容量D为0.1。情形B中h5已晚于两项期限，必须在h3恢复全部0.2，因此最低D为0.2。这里容量增加来自有效恢复窗口变窄，两种情形的瞬时调用峰值相同，也没有改变分离承诺相加的规则。

控制情形进一步说明了边界：

- 将期限各放宽1小时后，情形B可在h3、h5分两次恢复，最低D回到0.1。
- 将效率改为0.85、保留原期限时，情形B需要恢复用电约0.2353，但到期前最多只有0.2的清洁恢复额度；在这个小模型内增加D也不能完成工作。
- 在情形A中，D=0.1时“等到到期才恢复”的规则失败，但当前信息下的及时恢复规则成功。特定策略失败不能解释为所有安排都不可行。

全部6种清洁时序、3种期限和2种效率组合均保留，共36个构造案例。其中24个有有限D，12个在小模型内因到期前资源不足而无有限D。这些是精心构造的机制例，不是经验样本比例。

最小D由所有工作子集的恢复供给条件精确求出，再用独立的有理数最大流核对全部工作安排。另检查只读取当前额度和已产生债务的恢复规则：在各案例的最小D（无有限D时用固定探针）上，分别改变未来请求和恢复额度，共432项共同前缀检查。这些有限例与代码结构检查不代替原协议在全部训练支持上的同一因果策略证明。

## 与设备分期投装的联系

一个附加算例保持基准业务0.2，将可恢复计算余量写为“已投运计算容量K减去当前业务占用”。

| 已投运容量K | 情形A | 情形B |
|---|---|---|
| 0.3，余量0.1 | 可以完成，最低D=0.1 | 到期前无法恢复全部工作 |
| 0.4，余量0.2 | 可以完成，最低D=0.1 | 可以完成，最低D=0.2 |

因此，同样的业务需求可能对应不同的阶段性设备余量要求。这给出了研究分期投装的一个具体连接：新增设备既可能承接新业务，也可能提供补做延期任务的空间。

该算例尚未优化投资、建设工期或电网扩建，也未计入闲置设备功耗和成本，不能据此认定提前建设更经济。完整建设问题还必须让业务需求保持外生，比较相同服务目标，并根据当时可见的信息决定后续投装和工程启动。

## 创新性判断与下一步

上述小例证明了恢复时序机制成立，但这种一般机制本身已有相邻研究。Fan和Zhao已将工作负荷队列与可交付容量承诺联系起来；Khanal等的flexible tier具有循环积压及补做窗口，其interruptible tier另有深度、持续时间、爬坡及事件间最小恢复间隔。因此，本次结果不支持把“恢复很重要”或“小模型容量翻倍”直接写成独立创新。[Fan和Zhao，2026，文献库DC14](https://arxiv.org/html/2602.01508)、[Khanal等，2026，DC15](https://arxiv.org/html/2608.19622)。

建设方向也需要具体差异：Shao等已有15年数据中心与电力设施的联合投资规划，采用投资—运行的两阶段结构；Zhu等已联合优化多年度输电建设与跨中心任务迁移；Khanal等明确将投资顺序、分期投资价值和内部任务调度列为后续研究。因此，较值得继续检验的候选问题是：**当业务和工程进度逐步揭示时，由已投运设备及任务期限决定的恢复能力，是否会改变后续设备投装、容量接入和电网工程启动决策？** [Shao等，DC17](https://arxiv.org/html/2510.25118)、[Zhu等，DC19](https://arxiv.org/html/2610.13032v1)、[Khanal等的讨论](https://arxiv.org/html/2608.19622#S3)。这仍是候选缺口，不是优先权结论。

建议下一轮按以下顺序推进：

1. **明确清洁额度与业务映射。** 解释R、w、可延期比例及恢复余量如何代表目标项目；核对两类服务是否必须分别兑现、同一次实际削减能否同时满足两类要求。材料不足时，明确采用条件机制研究。若提出新合同，应有独立依据并保留旧负结果。
2. **拟定一个固定接入点、两至三期设备模块和一个电网候选工程的投资模型。** 保持业务需求与最终服务目标一致，对比预先确定计划与随信息调整计划。用现有运行层约束推导每期可兑现的柔性，不能始终按最终设计容量分配柔性。
3. **先检验建设决策是否改变。** 若内部调度与恢复约束确实改变投装或工程时点，并能解释变化条件，再考虑扩大模型。若只重复“恢复重要”或只出现预设规则直接导致的差异，应收缩主张。

当前工作仍保留原论文定位。本次没有产生正式容量、经验风险或工程安全结论，也没有为168/192小时执行提供运行许可或资源预算。
