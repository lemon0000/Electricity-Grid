# 科研实验跨电脑自动闭环流程

## 1. 目标

实现以下循环：

~~~text
家里 Windows 开始实验
        ↓
实验结束，上传结果到 GitHub
        ↓
公司 Mac 获取实验结束信息
        ↓
用 Trae 分析结果、修改代码
        ↓
上传新的代码版本和实验触发标签
        ↓
家里 Windows 自动拉取指定版本
        ↓
开始下一轮实验
~~~

分工原则：

- 公司 Mac + Trae：负责代码修改、调试、结果分析和实验方案设计。
- 家里 Windows + Codex：只负责拉取指定代码、运行实验、保存日志和上传结果。
- GitHub：负责保存代码版本、实验触发标签和可追溯结果。

Codex 不负责高难度分析，也不自动修改源代码。

## 2. GitHub 分支和标签约定

建议使用以下结构：

~~~text
main                    稳定版本
experiment               当前正在迭代的实验代码
experiment-results       实验结果分支
run-YYYYMMDD-NNN         不可变的实验触发标签
~~~

示例：

~~~text
run-20260814-001
run-20260814-002
run-20260814-001-r2
~~~

规则：

1. 普通代码提交只推送到 experiment，不会自动启动实验。
2. 只有创建并推送 run-* 标签后，家里电脑才启动实验。
3. run-* 标签一旦使用，不得复用、删除或强制覆盖。
4. 每个标签必须对应一个明确的 commit SHA。
5. 实验失败后也要上传失败信息；重试必须使用新标签，例如 run-20260814-001-r2。
6. experiment-results 只保存实验结果，不与 experiment 合并。

## 3. 公司 Mac 的一次性配置

### 3.1 获取最新分支

在公司 Mac 的 Trae 终端中执行：

~~~bash
cd /path/to/your/repository

git fetch origin --prune
git switch experiment
git pull --ff-only origin experiment
git status
~~~

如果本地还没有 experiment 分支：

~~~bash
git switch -c experiment --track origin/experiment
~~~

确认 GitHub 上的分支：

~~~bash
git ls-remote --heads origin experiment experiment-results
~~~

### 3.2 确认结果分支

先确认远端分支已经存在：

~~~bash
git ls-remote --heads origin experiment experiment-results
~~~

本项目当前的 `experiment-results` 已存在，且保留了代码历史。这不影响“结果分支只接收结果”的工作流；以后只向其添加 `results/<run-id>/` 下的轻量工件即可。

不要在已有的 `experiment-results` 分支上执行 `git switch --orphan`、`git rm -rf .`、强推或重建分支。这些操作会改写已有历史，并可能删除已上传结果。

如果未来要将结果分支迁移为 orphan 分支，必须作为独立迁移任务：先备份远端分支和全部结果、经人工确认后新建分支、验证结果可读性，再切换执行器配置。该迁移不属于日常实验流程。

### 3.3 配置 .gitignore

源代码仓库不应提交数据集、模型权重和大型实验输出。根据项目情况补充 .gitignore：

~~~gitignore
.env
*.key
*.pem
data/
datasets/
checkpoints/
models/
outputs/
runs/
__pycache__/
.venv/
.idea/
.vscode/
~~~

### 3.4 固定实验入口

建议将实验的真实启动命令固定在仓库中，例如：

~~~text
scripts/run_experiment.ps1
~~~

示例模板：

~~~powershell
$ErrorActionPreference = "Stop"

# 由家里 Windows 上的配置文件提供
. "D:\research\agent\experiment-config.ps1"

$tag = $env:RUN_TAG
$commit = $env:RUN_COMMIT
$runId = $env:RUN_ID
$runDir = $env:RUN_DIR
$artifactDir = $env:RUN_ARTIFACT_DIR
$configPath = "configs\experiment.yaml"
$configSha256 = (Get-FileHash -Algorithm SHA256 $configPath).Hash.ToLowerInvariant()
$command = "$($env:PYTHON_EXE) train.py --config $configPath"

New-Item -ItemType Directory -Force $runDir | Out-Null
New-Item -ItemType Directory -Force $artifactDir | Out-Null

$startedAt = Get-Date -Format o

@(
    "run_id=$runId"
    "source_tag=$tag"
    "source_commit=$commit"
    "config_sha256=$configSha256"
    "command=$command"
    "started_at=$startedAt"
    "status=running"
) | Set-Content (Join-Path $runDir "run-info.txt")

$runStatus = "failed"
$exitCode = 1
$failureMessage = $null

try {
    # 替换为真实的实验命令
    & $env:PYTHON_EXE train.py --config $configPath 2>&1 |
        Tee-Object (Join-Path $runDir "experiment.log")

    if ($LASTEXITCODE -ne 0) {
        throw "实验进程退出，退出码：$LASTEXITCODE"
    }

    $runStatus = "success"
    $exitCode = 0
}
catch {
    $failureMessage = $_ | Out-String
    $failureMessage | Set-Content (Join-Path $runDir "error.txt")
}
finally {
    $finishedAt = Get-Date -Format o
    @(
        "finished_at=$finishedAt"
        "status=$runStatus"
    ) | Add-Content (Join-Path $runDir "run-info.txt")
    $runStatus | Set-Content (Join-Path $runDir "status.txt")

    [PSCustomObject]@{
        run_id = $runId
        source_tag = $tag
        source_commit = $commit
        status = $runStatus
        start_time = $startedAt
        end_time = $finishedAt
        error = $failureMessage
    } | ConvertTo-Json -Depth 4 | Set-Content (Join-Path $runDir "status.json")

    # 只向 $artifactDir 写入可上传摘要，完整日志保留在 $runDir。
    # 外层执行器必须在本脚本退出后补齐 metrics.json、summary.md 和 manifest.json；
    # 对失败/超时，metrics 与 summary 只能记录“不可用”及运行原因，不能推断科研结论。
    Copy-Item (Join-Path $runDir "run-info.txt") (Join-Path $artifactDir "run-info.txt") -Force
    Copy-Item (Join-Path $runDir "status.txt") (Join-Path $artifactDir "status.txt") -Force
    Copy-Item (Join-Path $runDir "status.json") (Join-Path $artifactDir "status.json") -Force
    if (Test-Path (Join-Path $runDir "error.txt")) {
        Copy-Item (Join-Path $runDir "error.txt") (Join-Path $artifactDir "error.txt") -Force
    }
}

exit $exitCode
~~~

需要替换：

- Python 或 Conda 环境路径；
- 实验入口文件；
- 配置文件路径；
- 数据集路径；
- 输出目录；
- 需要上传的摘要文件。

提交基础配置：

~~~bash
git switch experiment
git add scripts/run_experiment.ps1 .gitignore
git commit -m "Add reproducible experiment entrypoint"
git push origin experiment
~~~

在家里 Windows 配置完成前，不要创建正式 run-* 标签。

## 4. 家里 Windows 的一次性配置

### 4.1 建议目录

~~~text
D:\research\code       代码仓库
D:\research\results    experiment-results 分支工作目录
D:\research\runs       每次实验的独立 worktree 和完整输出
D:\research\agent      状态文件和本地配置
D:\research\data       数据集
D:\research\models     模型权重
~~~

在 PowerShell 中创建：

~~~powershell
New-Item -ItemType Directory -Force D:\research\code
New-Item -ItemType Directory -Force D:\research\results
New-Item -ItemType Directory -Force D:\research\runs
New-Item -ItemType Directory -Force D:\research\agent
~~~

克隆两个目录：

~~~powershell
git clone -b experiment 你的GitHub仓库地址 D:\research\code
git clone -b experiment-results 你的GitHub仓库地址 D:\research\results
~~~

### 4.2 配置 GitHub 写权限

家里 Windows 需要能够拉取代码，并将结果推送到 GitHub。建议使用专用 SSH key，而不是个人主密钥。

~~~powershell
ssh-keygen -t ed25519 -C "home-experiment"
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"
~~~

将输出的公钥添加到 GitHub 仓库：

~~~text
Settings → Deploy keys → Add deploy key
~~~

如需上传 experiment-results，勾选 Allow write access。

测试连接：

~~~powershell
ssh -T git@github.com
~~~

将两个本地仓库的远程地址改成 SSH 地址：

~~~powershell
git -C D:\research\code remote set-url origin git@github.com:OWNER/REPOSITORY.git
git -C D:\research\results remote set-url origin git@github.com:OWNER/REPOSITORY.git
~~~

### 4.3 配置实验环境

创建：

~~~text
D:\research\agent\experiment-config.ps1
~~~

示例：

~~~powershell
$env:EXPERIMENT_ROOT = "D:\research\runs"
$env:DATA_ROOT = "D:\research\data"
$env:MODEL_ROOT = "D:\research\models"
$env:PYTHON_EXE = "C:\Users\YOUR_NAME\miniconda3\envs\research\python.exe"
~~~

建议在实验脚本中使用 Python 的绝对路径，不依赖后台任务中的 conda activate。

`D:\research\agent` 还必须包含由执行器维护的 `completed-runs.json`。它是本机执行状态，不提交到 Git，建议初始内容为：

~~~json
{
  "schema_version": 1,
  "completed_runs": []
}
~~~

每条已完成记录至少包含 `run_id`、`source_tag`、`source_commit`、`status` 和 `results_pushed_at`。无论实验本身成功、失败还是超时，只有该轮结果已成功推送到 `experiment-results` 后，才可写入这份状态文件。

### 4.4 保持电脑可执行

家里 Windows 需要：

- 保持开机；
- 接通电源时不要自动睡眠；
- Codex 桌面应用保持运行；
- 数据集和模型目录对当前 Windows 用户可读；
- D:\research 对当前 Windows 用户可写；
- 网络可以访问 GitHub。

## 5. 家里 Codex 的执行任务

在家里 Windows 的 Codex 中配置一个固定、低复杂度的定时任务。

建议提示词：

~~~text
你是家里 Windows 电脑上的无人值守实验执行器。

工作目录：D:\research\code
结果目录：D:\research\results
运行目录：D:\research\runs
状态目录：D:\research\agent

你只负责拉取指定版本、运行实验、上传结果，不负责修改源代码、分析代码或设计下一轮实验。

每次运行执行以下流程：

1. 只调用固定脚本 `D:\research\agent\run-pending-experiment.ps1`，不阅读、分析或修改项目源代码。
2. 脚本先取得独占执行锁；若已有有效锁，输出 `NOOP` 并退出，避免两个定时任务同时运行或同时上传。
3. 脚本执行 `git fetch --prune --tags origin`，列出所有符合 `run-YYYYMMDD-NNN` 或 `run-YYYYMMDD-NNN-rN` 格式的**注释标签**。
4. 按标签名的自然顺序找到第一个未出现在 `completed-runs.json` 中的标签；不得只检查“最新标签”，避免跳过较早的未运行实验。
5. 对该标签解析完整 40 位 commit SHA；若标签不是注释标签或不能解析，停止并报告。
6. 若同名运行目录不存在，使用 detached worktree 创建独立目录：
   `git worktree add --detach D:\research\runs\<run-id> <tag>`。
7. 若同名运行目录已经存在但没有终态 `status.json`，停止并报告，绝不覆盖或重跑。
8. 若同名运行目录已有终态工件但尚未记录为完成，只重试结果发布；不得再次执行实验。
9. 在新建 worktree 中调用固定的 `scripts\run_experiment.ps1`，并传入 `RUN_ID`、`RUN_TAG`、`RUN_COMMIT`、`RUN_DIR`、`RUN_ARTIFACT_DIR`。
10. 记录 run_id、source_tag、source_commit、配置哈希、实际命令、开始时间、结束时间和运行 status。
11. 无论实验成功、失败还是超时，都生成 status.json、metrics.json、summary.md、run-info.txt、manifest.json 和必要的错误信息；失败和超时只能描述运行状态。
12. 将摘要工件复制到 `D:\research\results\results\<run-id>`，在 `experiment-results` 分支中提交并 push。
13. 只有结果 push 成功后，才将该标签、完整 SHA、运行 status 和推送时间原子写入 `completed-runs.json`。
14. 如果没有待处理标签，输出 `NOOP`；每次最多处理一个标签。
15. 如果需要重试实验本身，必须使用新的 run-* 标签，不得复用旧标签。

禁止：

- 修改 main 或 experiment 分支；
- 修改源代码；
- 删除或覆盖已有运行目录；
- 上传数据集、模型权重、密钥和超大原始日志；
- 自动改变实验参数；
- 根据失败、超时或缺少结果自动下科研结论。
~~~

从省 token 和可靠性角度，Codex 定时任务只调用固定 PowerShell 执行器，不要每次都分析整个代码库。脚本本身应负责所有 Git、状态、运行与上传操作；Codex 只报告脚本的 `NOOP`、已启动、已上传或异常状态。

执行锁可使用 `D:\research\agent\executor.lock`，内容至少包含 PID、主机名、开始时间与当前 `run_id`。脚本必须在 `finally` 中释放自己创建的锁。发现陈旧锁时，不得自动删除；应先检查 PID 是否仍存在，再由人工确认后清理。

## 6. Worktree 执行方式

家里 Windows 不要在 D:\research\code 中直接切换到某个标签运行。应保持代码仓库作为控制目录，用 detached worktree 运行固定版本：

~~~powershell
cd D:\research\code
git fetch --tags origin
git worktree add --detach D:\research\runs\run-20260814-001 run-20260814-001
~~~

运行代码：

~~~powershell
cd D:\research\runs\run-20260814-001
$env:RUN_ID = "run-20260814-001"
$env:RUN_TAG = "run-20260814-001"
$env:RUN_COMMIT = (git rev-parse HEAD)
$env:RUN_DIR = "D:\research\runs\run-20260814-001"
$env:RUN_ARTIFACT_DIR = "D:\research\agent\artifacts\run-20260814-001"
powershell -ExecutionPolicy Bypass -File .\scripts\run_experiment.ps1
~~~

运行结果中必须记录完整 SHA：

~~~text
run_id=run-20260814-001
source_tag=run-20260814-001
source_commit=<40位完整SHA>
~~~

实验结束后可以保留 worktree 作为复现现场。确认不再需要时，再由人工清理：

~~~powershell
cd D:\research\code
git worktree remove D:\research\runs\run-20260814-001
~~~

不要在实验运行期间清理对应 worktree。

## 7. 结果文件规范

每次运行至少生成：

~~~text
results/<run-id>/
├── status.json
├── metrics.json
├── summary.md
├── run-info.txt
├── manifest.json
└── error.txt              # 失败或超时时生成
~~~

`status.json`、`run-info.txt` 与 `manifest.json` 是每轮必需工件；`metrics.json` 和 `summary.md` 可以在运行失败时为空值或说明不可用，但文件仍应生成。`manifest.json` 至少列出除自身外每个上传文件的相对路径、字节数和 SHA-256，以便公司 Mac 验证结果传输完整性。

run-info.txt 至少记录：

~~~text
run_id=run-20260814-001
source_tag=run-20260814-001
source_commit=<full-40-char-sha>
config_sha256=<sha256>
command=<exact-command>
start_time=<ISO-8601>
end_time=<ISO-8601>
status=success|failed|timeout
~~~

status.json 示例：

~~~json
{
  "run_id": "run-20260814-001",
  "source_tag": "run-20260814-001",
  "source_commit": "<40-char-sha>",
  "status": "success",
  "start_time": "2026-08-14T20:00:00+08:00",
  "end_time": "2026-08-14T23:30:00+08:00",
  "metrics": {
    "objective": null,
    "best_value": null
  }
}
~~~

`status` 只能取 `success`、`failed` 或 `timeout`。它描述进程和工件状态，不是模型可行性、安全性、认证状态或科研结论。

正式求解实验中，以下情况只能记录为运行状态，不能自动解释为模型结论：

- 实验进程失败；
- 超时；
- 没有 incumbent；
- frontier 未完成；
- 审计未完成；
- 日志缺失；
- 结果文件不完整。

## 8. 家里 Windows 上传结果

进入结果仓库前，执行器必须先确认本次摘要目录已生成。首次发布时，将其复制为唯一目标目录；若同名目录已经存在，必须比较 `source_commit` 与 `manifest.json`：相同则只重试 `push` 或完成状态登记，不同则停止并报告，绝不覆盖。

进入结果仓库：

~~~powershell
cd D:\research\results
git switch experiment-results
git pull --ff-only origin experiment-results
~~~

复制本次结果：

~~~powershell
$required = @("status.json", "metrics.json", "summary.md", "run-info.txt", "manifest.json")
$artifactDir = "D:\research\agent\artifacts\run-20260814-001"
foreach ($name in $required) {
    if (-not (Test-Path (Join-Path $artifactDir $name))) {
        throw "缺少必需工件：$name"
    }
}
New-Item -ItemType Directory -Force "results\run-20260814-001" | Out-Null
Copy-Item (Join-Path $artifactDir "*") "results\run-20260814-001\" -Force
~~~

提交结果：

~~~powershell
git add "results\run-20260814-001"
git commit -m "Add results for run-20260814-001"
git push origin experiment-results
~~~

只有 git push 成功后，才将一条完成记录追加到 `completed-runs.json`：

~~~powershell
$statePath = "D:\research\agent\completed-runs.json"
$state = Get-Content $statePath -Raw | ConvertFrom-Json
$state.completed_runs += [PSCustomObject]@{
    run_id = "run-20260814-001"
    source_tag = "run-20260814-001"
    source_commit = "<40-char-sha>"
    status = "success"
    results_pushed_at = (Get-Date -Format o)
}
$state | ConvertTo-Json -Depth 4 | Set-Content $statePath
~~~

应在写入前检查该 `run_id` 与 `source_commit` 不存在；状态文件应先写入同目录临时文件，再用 `Move-Item -Force` 原子替换。即使实验失败，只要失败日志和状态成功上传，也应更新 `completed-runs.json`，避免无限重复同一个失败实验。

## 9. 公司 Mac 获取实验结果

公司 Mac 不需要把结果分支合并到代码分支。

查看最新结果：

~~~bash
cd /path/to/your/repository
git fetch origin experiment-results
git log origin/experiment-results --oneline -10
~~~

查看具体摘要：

~~~bash
git show origin/experiment-results:results/run-20260814-001/summary.md
git show origin/experiment-results:results/run-20260814-001/status.json
~~~

然后修改代码：

~~~bash
git switch experiment
git pull --ff-only origin experiment
~~~

用 Trae 修改、测试并提交：

~~~bash
git add 需要提交的文件
git commit -m "根据 run-20260814-001 调整代码"
git push origin experiment
~~~

准备下一轮实验：

~~~bash
git tag -a run-20260814-002 -m "运行实验002"
git push origin run-20260814-002
~~~

## 10. 完整循环示例

### 第 1 轮：公司 Mac 发起

~~~bash
git switch experiment
git pull --ff-only origin experiment

# Trae 修改代码
git add .
git commit -m "调整实验参数"
git push origin experiment

git tag -a run-20260814-001 -m "运行实验001"
git push origin run-20260814-001
~~~

### 第 1 轮：家里 Windows 执行

~~~powershell
cd D:\research\code
git fetch --tags origin
git worktree add --detach D:\research\runs\run-20260814-001 run-20260814-001

# Codex 执行实验
$env:RUN_ID = "run-20260814-001"
$env:RUN_TAG = "run-20260814-001"
$env:RUN_COMMIT = (git -C D:\research\runs\run-20260814-001 rev-parse HEAD)
powershell -ExecutionPolicy Bypass -File D:\research\runs\run-20260814-001\scripts\run_experiment.ps1

# 上传摘要结果
cd D:\research\results
git pull --ff-only origin experiment-results
git add .
git commit -m "Add results for run-20260814-001"
git push origin experiment-results
~~~

### 第 2 轮：公司 Mac 根据结果修改

~~~bash
git fetch origin experiment-results
git show origin/experiment-results:results/run-20260814-001/summary.md

git switch experiment
git pull --ff-only origin experiment

# Trae 修改代码并测试
git add .
git commit -m "根据第一轮结果修改"
git push origin experiment

git tag -a run-20260814-002 -m "运行实验002"
git push origin run-20260814-002
~~~

然后家里 Windows 自动执行第 2 轮。

## 11. 实验完成后的稳定版本

当某个实验版本经过验证后，在 GitHub 上创建 Pull Request：

~~~text
experiment → main
~~~

合并到 main 后，下一轮继续在 experiment 分支迭代，或者从新的 main 创建新的实验分支。

experiment-results 永远不合并回 main。

## 12. 常见问题

### 家里没有发现新实验

检查：

~~~powershell
cd D:\research\code
git fetch --tags origin
git tag --list "run-*"
~~~

确认公司 Mac 已执行：

~~~bash
git push origin run-YYYYMMDD-NNN
~~~

### 同一个实验重复运行

检查：

~~~powershell
Get-Content D:\research\agent\completed-runs.json
Test-Path D:\research\runs\run-20260814-001
~~~

状态文件已有相同 `run_id + source_commit` 时，执行器必须跳过。运行目录存在且已经有终态工件、但状态文件没有该记录时，只允许重试结果上传；运行目录存在但没有终态工件时停止并报告。任何情况下都不得覆盖运行目录或远端同名结果。

### 结果推送失败

先检查 SSH：

~~~powershell
ssh -T git@github.com
~~~

再检查远程地址：

~~~powershell
git -C D:\research\results remote -v
~~~

结果未成功推送前，不要更新 `completed-runs.json`。

### 代码和结果混在一起

确认：

- 代码仓库使用 experiment；
- 结果仓库目录使用 experiment-results；
- 实验运行使用 D:\research\runs\<run-id> worktree；
- 不要在 D:\research\code 中直接切换标签运行。

## 13. 最终原则

~~~text
普通提交 ≠ 启动实验
run-* 标签 = 明确、不可变的启动请求
实验结束 ≠ 实验成功
结果推送成功 = 本轮任务已被消费
失败重试 = 新标签
完整 SHA + 配置哈希 = 可复现依据
~~~

公司 Mac 的 Trae 负责开发和分析，家里 Windows 的 Codex 负责固定流程执行。这样可以让实验持续运行，同时把高 token 的代码理解、修改和结果分析集中到公司电脑上完成。
