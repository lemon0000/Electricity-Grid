# Integrated bootstrap and global slot ownership

2026-10-09. DESIGN_ONLY_UNIMPLEMENTED. Root remains the sole writer.
This follows the 980-pin N symbolic coverage unit and phase owner design_v2.
It changes no scientific contract, source support, threshold or run authority.

## Implementation order

Implement bootstrap0 and its private study slot journal together, before the
hour1+ owner capability. The existing owner constructor already requires a
fresh accepted N0 terminal; it cannot be the owner of the first N execution.
Do not publish a detached claim-token API as an intermediate execution permit.

The bootstrap declaration binds a fixed study root, fixed global journal root,
bootstrap root and prospective controller/owner/holder roots, the exact pinned
symbolic manifest, unresolved training_ub family/ordinal, slot0 and a concrete
static profile. Current controller support is training_ub only. The four-family
symbolic catalog does not extend that support. Proof-terminal obligations and
other families must be rejected before scientific source loading.

A filesystem lease protects only its declared namespace. It does not establish
that no alternative study root exists. Eventual sealed execution configuration
must bind the single authoritative study/global-registry paths and externally
retained head. The symbolic manifest and caller-selected paths cannot do that.

## Profile and source boundary

Before attempt: validate pure declarations, fixed paths, hashes, profile fields
derivable from typed configuration, slot0 and capacity. No source row, network
loader or controller construction occurs. Synthetic profile examples are not
execution profiles and must fail the concrete configuration correspondence.

After attempt and matching global claim: internally load the static network and
recompute network/DC/config/specification/limits/hour-budget/implementation,
stage-order, origin and need-rule identities. Require exact correspondence to
the declared profile. The fixed232 stage claim additionally needs its exact RTS
profile validation. A mismatch consumes the attempt and records a typed stop.

Static network construction must discard chronological hourly points, as the
existing normal_h1_source.static_network does. The current scientific source
row used for N remains internally loaded by the owned controller after its
capability and headroom checks; the caller never provides a pre-read identity.

## Bootstrap persistence

1. Hold the bootstrap lease and operation guard; replay its journal and the
   global journal against independently retained heads.
2. Check complete success/failure branch logical capacity in both journals.
3. Compute a non-circular claim proposal from static declarations and roots.
4. Persist bootstrap attempt, then the unique global slot claim referencing
   that exact attempt. Reject every second root for an already claimed slot.
5. After exact correspondence, load/validate the network/profile and construct
   the new192 controller internally.
6. Persist exact release_intent before entering the native-capable controller.
   Consume an exact live bootstrap/controller operation capability once.
7. The controller checks headroom, loads the current source internally, then
   writes clock/parent intents and runs N through its controlled Job path.
8. Record the global terminal with exact parent/clock/obligation terminal,
   request and projection references. Rejected/unresolved outcomes remain so.
9. Only after the N0 terminal is fixed, create the phase TicketHolder/owner and
   consume N0 with the common Rref/business/A paired transaction. A failure
   here retains pending_post_N and cannot cause N0 to run again.
10. Mutually attach the exact owner/controller instances for subsequent hours.

The global journal has claim, release_intent and terminal states. Claim consumes
the slot; release_intent marks entry into potentially native execution. A
release without a terminal is execution/commit indeterminate and blocks retry.
Pre-release metadata may be reconciled explicitly within the same attempt;
this cannot create another claim or another root. Constructors must not silently
replay effects. Unknown writes preserve files and poison the active handle.

Global journal mutation requires same PID/thread, fixed lease and configuration,
fresh replay/index of all claims, external retained head and bounded records.
Head-retention callbacks are a trust boundary for retention only. They cannot
return producer permission. Physical allocation and full-study storage remain
separate resource gates.

## Hour1+ transaction

One owner.run_next operation holds the same owner guard through fresh DB/holder
replay, internal need, capacity, slot resolution, claim and publication.
No need writes only episode_terminal; it must not claim a slot, read the next
row, enter headroom/clock, create a Job or call a producer.

For positive need use Holder -> Global claim -> Owner DB. Split the existing
internal _append into prepare-ticket and commit-prepared operations so the
global record binds immutable ticket bytes and exact holder/DB before/after
heads. This is an internal transaction seam, not a public capability factory.

The live capability binds exact owner/controller objects, PID/thread, active
operation nonce, study/profile/slot/claim, ticket, holder head, owner double
heads and controller parent/clock predecessors. It is single-use and expires
when the operation guard exits. No arbitrary callback or constructible JSON
record can grant this permission. Lock order remains owner -> controller ->
clock -> parent; validation must not reacquire the held owner lock.

Persist the global N terminal before the fresh source/Rref/business/A paired
commit. If the latter fails, retain pending_post_N and continue only from the
existing N terminal. Accepted predecessor terminal/projection is required for
instantiating the next slot; proof-reference edges never substitute for it.

## Failure matrix and required verification

| Window | Required behavior |
| --- | --- |
| Before any holder/bootstrap artifact | A later fresh operation may begin only if absence is established. |
| Holder write uncertain | Poison; reopen with external heads; never guess or retry N. |
| Holder exists, global claim absent | Recovery required; explicit first claim of the same ticket only. Competing claim is permanent conflict. |
| Holder+claim exist, DB absent | Explicitly commit that exact ticket; no new ticket or claim. |
| DB commit uncertain | Accept exact-before/exact-after only; before remains recovery-required. |
| DB without claim, or claim without required holder | Impossible state; stop. Bootstrap uses its own prior attempt instead of a holder. |
| Claim exists, release absent | No automatic execution; reconcile same-attempt metadata explicitly. |
| Release exists, N terminal absent | Execution/commit indeterminate; never call N again. |
| N terminal exists, paired outcome absent | pending_post_N; consume existing N evidence only. |

Tests must count source/network/controller effects before bootstrap attempt;
reject duplicate root/slot/profile/ordinal; inject failures before/after each
write across all stores; reject capability forgery, reuse, foreign thread and
expired operation; prove internal source load follows capability/headroom;
exercise accepted N0 to owner paired consume and hour1 positive/no-need paths.
Synthetic seams must be labelled, and cannot prove a real192 accepted prefix.
