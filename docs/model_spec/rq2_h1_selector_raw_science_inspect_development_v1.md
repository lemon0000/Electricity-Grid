# Detached fresh selector-capsule inspection

This development reader accepts a canonical absolute bridge directory, an external
retained terminal SHA256 and the full typed selector inputs/prior record prefix.
It creates no file, solver, Job, owner capability or retry authority. The closed
991-pin predecessor remains unchanged.

Exact ReplayLimits type and invariants are validated before any evidence read;
record size cannot be supplied by a duck-typed or mutated unchecked object.
After final evidence scans, implementation identity, request key, current package
and model observations, and both inspector/bridge scope are rechecked before return.

Four exact directory inventories and every bounded regular-file view are retained.
Canonical encoding is required for all artifacts, with the closed selector's own
encoding for its saved record. The external terminal pin is checked before scientific
replay. Capture binding/specification/export and raw intent/receipt/outcome are
verified through the existing source-view helper; complete and raw terminal require
separate exact reconstruction and fresh ingress inspection.

The current canonical LP stage and metadata are rebuilt from typed inputs. Three
equal fresh observations must reproduce the stored observations payload exactly.
The closed bridge audit decodes native/postsolve channels, rejects negative generation,
reconstructs the derived selector record and runs the full closed selector prefix
replay. Both saved record and entire bridge terminal must reproduce byte-for-byte.
Implementation/input, file bytes/identities and directory inventories/identities are
checked again before return. Ordinary concurrent changes and replacements reject;
this is a bounded read/recheck protocol, not a filesystem transaction or protection
against hostile arbitrary code in the same Python process.

Successful output means saved numerical consistency, fresh at return, with zero solver
calls. Historical native execution, owner consumption and retry flags remain false,
along with all 15 predecessor scope flags. A complete terminal after a producer's
after-write exception can be numerically consistent; the reader cannot infer whether
the producer returned. Missing terminal or any other required evidence is rejected
and retained for later diagnosis. The reader does not repair, re-execute or promote it.

An owner must retain its own durable attempt/head/ticket and expected bridge pin,
invoke inspection internally, and recheck its live operation before any commit.
Arbitrary inspection dictionaries and terminal existence are not capabilities.
Owner reconcile, Job/controller wiring, common Rref/A publication, full192 coverage,
resource admission, sealed official review and separate native authority remain open.
