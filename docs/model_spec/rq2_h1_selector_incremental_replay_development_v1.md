# H1 selector incremental numerical replay

2026-10-17. R3 DRAFT_NONAUTHORITATIVE. This implements a bounded performance
change inside one detached selector capsule audit. The unchanged
`rq2_h1_selector_replay_development_v1.md` defines the scientific mathematics.

`h1_origin_selector_incremental_replay_development_v1.py` verifies an incomplete
prefix with the old public replay once. A private process/thread-local,
nonserializable token retains that result. One append performs the same legacy
single-stage numerical transition and result construction. No combined-prefix
numerical replay occurs at append or tail validation. The legacy modules,
saved-record schema, selector policy and scientific selection identities remain
unchanged. The helper and raw bridge each have a separate versioned identity.

The new stage still performs both canonical model builds inside native replay,
assignment/completion, objective, residual and integrality recomputation,
status/count, finite LB/UB, absolute and relative gap, rational lock/deviation,
physical witness and final carry checks. Canonical locks come exclusively from
the native replay diagnostic's recomputed objective, including signed zero.
A failed new record retains the old error index/text and yields no successor;
a failed prefix or a suffix after failure is rejected by the old public replay.
The token admits one append and is poisoned by failed freshness/append checks.

At verify, append entry, append return and raw-audit return, fresh checks cover:

- exact input, full frame/disclosure/predecessor, policy, lane/power, selector,
  solver spec, limits, labels, record pins, lengths and aggregate caps;
- every old stage context and its canonical model structure, initial snapshot,
  scale, real package versions and solver options, plus the next-stage context;
- helper/legacy implementation identities and loaded function aliases, code,
  defaults and closure references, and physical acceptance constants.

This validation contract replaces repeated numerical evaluation of unchanged
old records with fresh context/runtime observations. It does not claim equal
observation counts, an arbitrary Python reflection sandbox or detection of
unobserved change-and-restore windows. Mutable source, registry, raw files,
controller observations and persistence callbacks are not cached by this helper.
The token is neither a persistent checkpoint nor owner/native authority.

`h1_selector_raw_science_development_v2.py` explicitly imports the helper and
binds its bytes into bridge identity. Its `_audit_stage` uses one verified
prefix and one appended numerical transition. Its `_run_stage` retains the
original separate request and persistence checks; no claim is made that this
two-module change closes whole-workflow performance. It cannot be substituted
under the v1 module name. Actual pipeline integration requires versioned static
successors of the timed-stage/sequence/snapshot/worker dependency route with
their own identity closure and integration evidence.

Acceptance requires byte-for-byte differential results against the unchanged
old combined replay for Rref and Actual, all prefix lengths, signed zero,
failures, gap/lock/status/count/assignment/residual/integrality and final carry;
numeric call counts; and drift at prefix, append and tail boundaries. Test
success, local timing and PRE_SEAL findings grant no official review, whole-chain
acceptance, resource admission, native execution or formal-run authority.
