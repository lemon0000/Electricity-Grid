## 查询与调用DAG

每个(plan, clean path, method, hour)生成独立请求身份，覆盖fixture/网络/清洁路径/小时/方法/角色/负荷/明确F/X分解/事故/基准父节点/redispatch/rating/目标正则项。clean_path也进入父frame一致性检查，即使物理问题相同也不跨清洁路径借父点；当前不实行纯物理问题跨路径复用。同和的另一组F/X不得重解释原raw点；实际合法性审核必须匹配查询内的准确分解。完整BoundQuery身份还绑定父完整点和KKT证据，未提供它们的corrective仅为request描述。三方法共享当期外生输入，但当前只是查询接口，不能宣称三网络评价已执行。

1. `normal_contract_C`：完整C，无削减，健康网络经济基准。
2. 每事故`fault_firm_F`：固定F、无削减，绑定完整C基准出力及corrective界。
3. 每事故`fault_raw_need`：完整C、削减上限C，以最小POI削减为目标，保存原始请求。只有其实际削减≤X且剩余≥F才属于合法X；完整点可供合法性复核，但物理点本身不证明最小性。超X的原请求保留，不能先截掉。
4. `reference_base_P0`：当前P0的健康网络、无削减经济基准。实际有声明退出时另建`reference_raw_need`，同样保留原请求，合法调用还受活跃X、事件/爬坡/能量约束。正常状态不借X调用掩盖供电不足。
5. `recovery_min_P`、`recovery_max_P`：在实际拓扑、相同P0基准/corrective界及[0,C]范围内分别最小/最大计量负荷。两端需各自可核的最优证据后才可用于连续凸DC投影区间；不能仅用最大值假定从0起可供电。
6. 固定策略选择之后才生成`actual_P`，固定真实取电、零削减，按实际拓扑独立核验；本轮尚未接策略/journal执行。

S=69时合同层1+2S=139个求解节点；每小时参考基准1、实际退出时原请求1、恢复两端2、实际点最多1，共正常143/实际退出144个节点上界。legal-X是raw点的条件合法性审核，不另生成默认求解。0原始削减有健康基准见证时可解析为0，不折扣其余审计。instantaneous无需恢复两端，但三方法的实际运行与完整约束回放必须按各自执行图另计。以上是逻辑节点预算，不是实际solver调用实测、wall或主实验准入。

## 构模与审计合同

[查询/构模模块](../../src/staged_rts24_development_v1.py)只构建Pyomo模型，不导入SolverFactory或调用求解器。模型保存全bus/gen/branch索引，节点功率平衡、DC支路方程、热限、停运零输出、Pmin/Pmax及已绑定同小时再调度界。角度用rad：f=baseMVA/(x*tap)×(theta_from−theta_to−shift)。只接受连通声明拓扑，孤岛拒绝，不增加无限slack。

有corrective父节点的查询必须提供相应基准完整点及独立可核的经济KKT证据。只提供物理可行父点拒绝绑定；未提供父点仅可保留查询描述，不能以占位发电点冒充公共网络基准。父查询身份、完整点、KKT证据和子输入共同进入绑定身份，每次bind、构模及子点审计都会重新核验，成本不能省略。

[独立点审计](../../src/staged_rts24_audit_v1.py)不读取Pyomo约束、不求解、不调用构模函数，自行重算完整索引、有限数、节点平衡、支路方程、参考角、热限、事故元件零输出、机组界、同小时再调度与计量/削减界。MW残差沿用现有DC的1e-6，参考角1e-9rad；不能由writer自报feasible或残差代替。结果只说明该点符合声明约束，`minimum_established=false`；不解释timeout为不可行，也不从点见证推导最优容量。

另由`audit_economic_base`核验固定负荷、零削减、健康基准的凸QP KKT充分条件。消去固定meter/curtailment/参考角，令平衡等式为G−Pd−Pnet−out+in=0、支路等式为f−BΔθ=0；λ为平衡乘子，μ为支路乘子，上下界乘子非负。独立重算`2(a+1e-8)G+c+λ−lower+upper=0`、flow/angle stationarity、对偶符号及互补，KKT固定容差1e-6。原始点和完整dual数组必须绑定相同query/point SHA；缺项、非有限或KKT失败拒绝。只支持声明凸DC基准的数值最优性核验，不证明子查询最小削减、设备能力、动态响应或工程安全。三母线解析例特意给出满足KKT的报价/乘子，仅验证公式，不提供公共网结果。
