# 现有排除证据与恢复时序的小模型核查

2026-10-21，DRAFT_NONAUTHORITATIVE。本任务核查保存的 finite-v2 排除证据，并构造小型解析调度问题，帮助判断论文下一步的科学重点。用户已授权现有证据审计及小模型检验。正式协议、既有结果、运行门禁和论文主线均保持原状态。

## 核查对象

读取绑定的 `cell_exclusion_audit_v2_final.json`，独立重算全部1,900个cell的瞬时条件。先核验原始压缩CSV、coverage与协议的SHA256，再核对两条完整168小时训练窗口的行、连续源小时及12位half-even业务投影；电力源另核验UTC偏移、整点与时间戳每小时连续性，业务源仅有相对小时，不宣称独立UTC时钟。入口绑定原协议的tau、活动阈值和投影规则，拒绝不支持的参数语义或资源计划。重建全部300组算术、292份排除证明的完整envelope与1,900个cell身份；CSV保留三类身份和原状态，JSON保存闭合身份集合及其摘要。只核验本任务实际依赖；原报告全部传递依赖和normal/reference可达性不在此次重审范围。

方案A为 `y=R*w`、`q=max(w-y/alpha,0)`，先按原阈值归零，再比较 `q` 和 `f*w`。旧证明还允许服务不足及可用量各放宽一个tau；只有 `q-f*w-2*tau>0` 才排除这个局部放松集。因此这些证据排除同合同完整支持的相应规划臂，不是其余pair逐个执行失败，也不是holdout失败率。剩余44个cell只是这个证人未排除；所有network-only结论保持未知。

在忽略活动阈值且w>0时，该小时必要条件等价于 `alpha<=R/(1-f)`（f<1）。报告同时给出包含原阈值的精确枚举结果；不以简化比例替代原证明。

## 独立小模型

参数位于 `configs/rq2_novelty_mechanism_audit_v1.DRAFT.yaml`。6小时、恒定业务基准w=1/5、alpha=1/2、f=1/2。网侧仅h0调用1/10；h1的R=1/4产生CFE调用1/10，其余普通小时R=1/2。h2至h5中任选两个小时令R=1，共6种清洁时序。所有时序的任务量、grid/CFE调用序列、瞬时合计峰值、清洁份额边际及总额度完全相同，仅恢复额度的到达时间改变。headroom为rho*(1-w)=6/25，清洁恢复surplus为max(y/alpha-w,0)。

每次正调用生成等量待完成工作，h0/h1的两份工作分别在birth+lag到期，lag取2/3/4；eta取1或17/20，共36个构造案例。birth当小时不恢复该工作，到期小时先恢复再检查；每小时恢复功率不超过headroom、CFE surplus及D，且q+r<=D。调用小时surplus为零。每份工作必须完成，债务不能删除。网侧dispatch、启停、事故、所有原业务事件/累计预算和完整因果训练支持不进入小模型；小模型也使用不同的短期限。因此它既不是原协议的容量证书，也不被当作原模型的全局LB/UB。

对每个工作子集J，令E(J)为它们可恢复小时的并集。可分工作调度的二部流条件为：

`sum(work_j/eta for j in J) <= sum(min(D,u_t) for t in E(J))`。

u_t是独立于D的清洁/headroom上限。枚举全部3个非空工作子集，通过分段线性精确反解求最小D，并与调用峰值取最大。若即使D无限增大也不能满足某一子集，保存该割及缺口。另写独立Fraction残量网络最大流，验证每个最小D的全部工作安排与逐时约束。最大流只作为这个已知小场景的可行性oracle；因果性由另外只读当前额度与已产生债务的EDF规则及共同前缀扰动检查支持，不把逐场景最优值冒充同一因果策略的全支持容量。

两个控制分别撤去h2至h5的清洁恢复限制、执行“等到到期才恢复”的特定规则；调用小时仍不安排恢复。后者失败而最大流可行时，只证明该规则失败。所有6种时序、3种期限及2种效率全部保留，包含无时序影响及无解案例。产物保存grid/CFE分量、合计请求、逐时R与清洁额度；匹配比较显式核验两个请求分量、额度总量和峰值。432项共同前缀检查在各案例D（无有限D时取1）上改变未来q与u；它们只是有限后缀扰动检查，非独立因果oracle或全支持策略证明。到期后补完仍保留先前的deadline violation。

一个额外headroom算例把可恢复计算余量定义为K-w，比较K=3/10与2/5，其他条件相同。它仅说明投装容量可能通过恢复余量影响履约；没有电网建设变量、成本、建设工期、不确定信息树或投资目标，不声称完成建设协同规划或证明提前建设的经济优势。

## 全流程与预算

固定DAG：读取并核验绑定输入→重建168小时证人→重算1,900个瞬时条件及身份→36个工作子集解析问题→独立最大流及因果规则→CSV/JSON写入→回读→输入hash复核。没有solver、native、网络、子进程、回调、状态恢复或历史链重放。仅一次顺序执行，不并行、不调用原H1审计构造器。

原始CSV各读一次；300个不同alpha/f组合只做一次算术并保留全部cell身份，不能把不同theta的完整时序视为等价。输入单文件上限16MiB，输出总量4MiB，脚本墙钟上限45秒、阶段检查的进程peak RSS上限512MiB（非OS硬配额）。失败保留新attempt目录，不覆盖历史结果，不延长预算。普通pytest先覆盖边界、篡改拒绝与独立oracle；再以此脚本的小完整路径作为本包的有界代表性实测，记录阶段计时、RSS和输出大小。它只服务本诊断包，不为168/192小时运行提供预算。
