# 最小阶段评价规格：给定接入计划与连续任务恢复

日期：2026-10-22。状态：`DRAFT_NONAUTHORITATIVE`，工作包A的设计规格。适用范围为[当前交接](../plan/continuation_handoff_20261022.md)确定的单接入点、两至三期设备、一个候选电网工程和少量给定计划。本文件明确工作包B首例的机制规则；现实合同适用性及参数来源另按[阻塞登记](blocker_register.md)补齐。

## 1 评价对象与边界

输入为给定计划p、外生路径ω、固定业务柔性容量D和运行策略π。输出为逐小时状态、各阶段已观察缺口、任务期限结局和未知项。建设时点、F/X额度和D在评价前给定，业务需求不能随方案可行性缩减。先比较固定D下的履约判断；最低D及方案优劣只有在相应证据充分时另行定义。

工作包A仅形成设计；小案例实施见[工作包B计划](../plan/staged_deliverability_small_case_plan_v1.md)。本文件不创建冻结实验候选，不改变旧预注册、结果、manifest或运行门禁。旧四臂仍按其具名合同解释，不能直接把新阶段评价称作旧前沿结果。

## 2 三条进度路径与给定计划

统一使用连续物理小时t，区间为[t,t+1)，步长Δt=1 h。业务、设备、电网进度分别输入，在任一路径状态变化的小时形成阶段边界。阶段是汇总标签，不重置运行状态。

| 路径/计划 | 最小输入 | 进入的约束与输出 |
|---|---|---|
| 业务路径 | 任务批次j的到达a_j、当期基准任务量A_j、期限d_j、可延期比例f_j；w_t=Σ_{a_j=t}A_j/Δt | 当期可延期工作、任务完成余额、期限及阶段业务占用 |
| 设备路径 | 模块m的容量k_m、计划开始时间s_m、完整工期L_m、实际延期δ_m及可用状态 | τ_m=s_m+L_m+δ_m；u_{m,t}=1[t≥τ_m]；K_t=Σk_m u_{m,t}；待机用电与补做上限 |
| 电网路径 | 一项工程的开始时间s_G、工期L_G、延期δ_G、既有网络和实际增容映射 | τ_G=s_G+L_G+δ_G；v_t=1[t≥τ_G]；按v_t构造网络N_t及当期调用、恢复供电条件 |
| 给定接入计划p | 各时段F_t、X_t、设备安排、工程安排、D及固定策略标识 | 正常状态完整F_t+X_t校核、故障状态F_t及合同X调用、实际取电上限 |

模块与工程在τ对应小时开始时才可用。预计投运时间不能代替已经观察到的投运状态；不能追认此前缺口。首例以小时刻度压缩工程进度，只验证边界接线，不把小时工期解释为现实建设工期。

同一业务情景内，比较计划共享A_j、f_j、d_j、外部清洁路径和安全标准；设备及电网投运不同作为计划差异保存。业务快/慢达产之间允许需求路径不同，应分别配对比较计划，不能把不同需求下的差异解释成纯建设效应。计划不含业务需求的决策权。

初步机制矩阵为业务快/慢×电网按期/延期，设备路径单独记录。点数及实际时长在工作包C后确定。改变设备路径时须同时改变K和待机功耗，不能只增加恢复余量。

## 3 变量、单位与设备—任务—取电映射

首例使用同质、可分割、可抢占任务与同质设备。定义参考计算功率单位MW_c及工作量单位MWh_c；它们用于统一计算资源占用，不等同于接入点MW和MWh。每单位已投运设备在一小时最多处理1 MWh_c基准工作。异构任务适配与设备效率需要独立扩展，不能隐含在首例中。

| 符号 | 单位 | 定义 |
|---|---|---|
| K_t，w_t | MW_c | 已投运计算能力；外生任务的当期基准占用 |
| q_{j,t}，q_t | MW_c | 当期任务被延期的速率；q_t=Σq_{j,t}，仅a_j=t时可正 |
| r_{j,t}，r_t | MW_c | 为既有任务补做所占用的设备速率；r_t=Σr_{j,t} |
| D | MW_c | 双向调节容量，共享q_t+r_t≤D |
| b_{j,t} | MWh_c | 小时开始时任务j的未完成延期工作 |
| η_j | MWh_c/MWh_c | 每单位补做设备工作完成的原始任务量，0<η_j≤1 |
| z_t=w_t−q_t+r_t | MW_c | 当小时实际活动计算资源占用，0≤z_t≤K_t |
| P_idle,t，P_aux,t | MW | 已投运设备待机功率；固定配套功率 |
| β，γ | MW/MW_c，无量纲 | 每单位活动计算资源增加的IT功率；IT至设施计量点的乘数 |
| P_t，P_t^0 | MW | 实际取电；同设备、同任务且q=r=0的基准取电 |
| Y_t，y_t | MWh | 外部可归属清洁额度；实际分配给本计量点的同小时额度 |

最小映射为：

```text
P_idle,t = Σ p_idle,m u_m,t
P_IT,t   = P_idle,t + β z_t
P_t      = γ P_IT,t + P_aux,t
P_t^0    = γ (P_idle,t + β w_t) + P_aux,t
a        = γ β > 0
P_t      = P_t^0 − a q_t + a r_t
```

p_idle,m是已投运且保持开机模块的待机功率；首例不优化关机。γ覆盖随IT变化的冷却等配套负荷，P_aux只包含γ尚未覆盖的固定辅助负荷，来源表必须防止重复计量。设备完全空闲也承担已投运部分的待机功耗。η降低时，同一债务需要更多r及相应取电，不能同时再给P重复乘一个补做损耗系数。

首例假设所有模块共用β和γ，且两者在比较中固定。因此计算资源约束w−q+r≤K有效，但仍须单独检查P。换设备类型或负荷相关PUE时，a不再是统一常数，须新映射和验证。所有新旧接口均写明单位和归一化基准；旧模型的归一化D或物理MW不能直接当成MW_c。

即使w_t>K_t，也保存原始需求：若合法q足以暂缓并在期限内恢复，可继续评价；否则记录设备/业务缺口。P_t^0此时仅为声明的无延期参考需求，不能标成可实际执行的基准。设备侧缺口不能通过缩小w或忽略任务消除。

## 4 服务规则与清洁核算

### 4.1 首例采用的具名规则

采用`independent_additive_calls`：网侧和CFE侧各自登记的削减承诺，共同由一份业务资源兑现。同一单位延期只分配给一个承诺。实际总取电只计算一次；清洁核算仍使用实际P。该规则是机制比较假设，现实项目是否采用，需要合同及计量依据。

沿用现有聚合执行限制：q_t r_t=0。即同小时有正削减时不补做；没有削减时可按既有债务恢复。它比允许不同任务同时延期和补做的调度器更窄，所有首例对照均保持该限制。q+r≤D、z≤K仍各自检查。现有实现依据为[双向策略](../../src/rq2_joint_deliverability_boundary_v1/capacity_policy_bidirectional.py)及[聚合响应](../../src/rq2_joint_deliverability_boundary_v1/aggregate_response.py)；不能仅保留q+r约束就把这些旧接口解释成允许同时延期/补做。

令g_t为当前网络、当前参考取电P_t^0和已观察运行状态下所需的完整网侧削减请求，单位MW。它由实际网络接口返回，保存原请求及来源；不先截断到X、D或当期可延期工作。不能给所有建成网络复用一条固定g曲线。

当α>0时，CFE侧原始请求为：

```text
h_t = max(P_t^0 − Y_t/(α Δt), 0)       # MW
```

α=0时单独定义h_t=0，不做除法。α取值范围[0,1]。首例无其他清洁额度竞争者，Y_t是独立外生可归属额度，不从决策后的P、q或设备容量反算。

c_grid,t和c_cfe,t以MW_c表示各自实际兑现的延期量：

```text
q_t = c_grid,t + c_cfe,t
0 ≤ a c_grid,t ≤ g_t
0 ≤ a c_cfe,t ≤ h_t
s_grid,t = max(g_t − a c_grid,t, 0)    # MW
s_cfe_call,t = max(h_t − a c_cfe,t, 0) # MW
```

完整兑现要求两类s均为0，同时满足实际网络、任务与CFE约束。有资源不足时保留原始g、h、可执行动作与缺口，策略按网侧优先分配；网侧资源不足的轨迹不得标作安全可行运行。CFE削减产生的物理取电改善可以出现在潮流中，但不能抵扣另一份已经登记的网侧独立承诺。同样，网侧削减不能记作CFE承诺兑现。

首例不允许超过请求的额外服务削减，也不另设无请求的自主延期决策。若因此无法承接当期外生业务，记录设备/业务缺口，不生成无请求债务掩盖不足。实际网络若没有可行运行状态或返回未决，不推进依赖该物理状态的后续执行；保存失败/未决终态及当时账本。

在q=0的恢复小时，策略事先限制r≤D、r≤K−w，并在α>0时限制r≤max(Y/(αΔt)−P^0,0)/a；还须属于当期网络允许的供电范围并受已有债务、事件/休息和恢复功率上限约束。α=0时不施加清洁恢复上限。若基准业务本身已超设备或供电范围，不以负恢复上限掩盖，应记录对应缺口并执行合同定义的合法动作。

这项加总规则可能要求超过“仅使实际P同时满足网络与CFE条件”的削减量，属于合同差异。若以后研究允许同一次削减双重记账，须单列合同、保持各计划规则一致，并重新设计比较；不得把旧四臂标签自动移植过去。

### 4.2 F/X、实际运行与合同容量分别检查

F、X用计量点MW表示接入权，D用MW_c表示业务调节，g用MW表示网侧请求，三者分别报告。

- 正常状态按当时建成网络校核完整F+X，实际运行还须P≤F+X及网络平衡和限额。
- 声明故障状态的合同容量检查完整F及允许调用的X；不能因拥塞主动削减F。X的响应、持续时间、次数、能量及休息条件须显式给定，并跨阶段延续。
- 实际网侧承诺还满足0≤a c_grid≤X_active,t。首例接实际网络时，明确采用F优先加载的参考分解：P_F^0=min(P^0,F)，X_active=max(P^0−F,0)且须≤X。参考需求超出F+X时单列接入需求缺口；g超过可调用X时保留原请求和合同不足，不能改小g。F是受保护的接入权，不是实际取电下限；业务自主CFE移峰可以少用F，但不得据此把网侧削减F记为合规调用。
- 合同容量反事实检查与实际低负荷运行分开。实际P较低时的成功不证明完整F/X可交付；仅有设备D或aD也不证明可以新增同量X。
- 响应前/后安全遵守[既有模型规格第8–9节](formulation.md)。小时模型不能声称已核验亚小时响应；缺乏可信短时额定值时按预防性调用建模。
- 建成网络改变时，重新计算g，并对补做后的P重检供电条件。只用基准P算出g后，不得省略恢复小时的网络检查。

小案例的标量供电限额仅是接口替身；在接入实际网络、声明故障集合、响应合同和完整F/X校核前，其输出只支持数值闭环诊断。

### 4.3 小时CFE与服务记账的区别

```text
0 ≤ y_t ≤ Y_t
y_t ≤ P_t Δt
α P_t Δt ≤ y_t                # 完整小时匹配条件
e_CFE,t = max(α P_t Δt − Y_t, 0)
```

首例无储能、现场发电或出口，所有计量点取电、待机、补做及配套用电进入P。Y表示该小时适用核算边界内可归属电量，不追踪物理电子；未使用额度不跨小时结转。若多个用户分配额度，须增加同小时分配总和不超过外部总量的约束。

同时报告s_cfe_call（MW，独立削减承诺缺口）与e_CFE（MWh，实际匹配缺口），二者不能混称。网侧削减可能使实际CFE已达标而独立承诺仍未完全兑现。在补做小时q=0时，P增加，须重新检查αPΔt≤Y；不能沿用基准小时的CFE通过标志。

## 5 任务账本、期限与状态衔接

首例把当期基准任务作为一个批次j，在a_j到达。基准模型要求当小时执行未延期部分；q_{j,t}仅能来自当期可延期部分：

```text
0 ≤ q_j,a_j Δt ≤ f_j A_j
q_j,t = 0                         (t ≠ a_j)
r_j,t = 0                         (t ≤ a_j)
η_j r_j,t Δt ≤ b_j,t             (t > a_j)
b_j,t+1 = b_j,t + q_j,t Δt − η_j r_j,t Δt
```

当期执行A_j−q_j,a_j Δt，补做累计Ση_j r_j,t Δt。无永久丢弃，故每个批次的审计恒等式为：

```text
A_j = 当期完成工作 + 累计补做完成工作 + 当前未完成工作
```

已有前史债务另保留其原始A、已完成量、产生小时及期限。不能只传一个总MWh后重建期限。η只决定补做效率，不能把延期债务乘一个小于1的系数使工作消失。

d_j为最后允许完成的小时，d_j≥a_j。先执行该小时合法补做，再在小时末读取b_j,d_j+1；该值为到期未完成量。将首次到期时的违规量和时间永久保存。之后补做可减少当前债务，但不能抹去已发生逾期。

最小策略在无调用小时按期限最早优先（EDF，期限相同按批次ID）恢复，且只使用已到达任务和当前资源。逾期任务继续留账并按同一规则补做；不静默删除。策略失败只表明该策略在该路径未履约，不等于所有策略均不可行。

连续窗口传递完整批次账本、逾期历史、调用on/start/stop、持续时间、休息计数、次数/能量预算、前一小时动作、网络/设备状态及随机或策略状态。仅对合同明定的日/月边界重置对应预算。阶段边界、登记结束或工程投运均不重置债务和事件。

## 6 时间、信息与终态

每小时按以下顺序执行：

1. 读取上小时末完整状态；观察当前业务到达、设备/工程实际投运、当前网络状态与当前Y。
2. 更新本小时可用K及网络N；计算同口径P^0、g、h，保留请求来源和不可用信息。
3. 用固定π选择网侧/CFE延期分配或EDF补做，检查q+r≤D、q r=0、可延期份额、已有债务与z≤K。
4. 计算实际P，执行正常/已声明故障网络检查及小时CFE核算；保存动作、残差与缺口。
5. 更新各批债务，先记到期结局，再形成小时末状态和持久化记录；t+1只从该记录继续。

计划表可在开始时已知，未来实际延期和未揭示的业务/清洁路径不可读取。相同观测历史必须产生相同动作。完美信息离线调度仅作为另行标注的可行性oracle，不能充当留出执行策略。

登记区间[0,E)内发生的服务调用及其任务构成主要评价对象；后续观察[E,T)仍保留正常到达任务及全部资源占用，不能设为免费恢复期。继续产生的后续任务单独标记，防止混淆主要对象与延伸债务。选定T须覆盖主要对象期限，并报告后续对象仍未到期部分。

若输入提前结束，已观察缺口与逾期照常保留；未观察到期限的任务记为右删失，缺少求解/检查结果记为未决。不得把两者记为完成或数学不可行。非连续阶段窗口须提供可审核的完整前史与中间状态转移；没有转移依据时分别评价，不能直接拼接。

## 7 三种评价口径与可比较输出

三者共享外生输入、服务规则、设备功耗映射和同一次网侧请求来源。它们用于比较判断边界，不把简化检查通过称为完整履约。

共享的是请求生成规则与外生网络数据。若实际发电/爬坡状态受过去动作影响，各方法须从自己的连续物理状态生成当期请求，不能强制复制g；这时须单列其调用差异。B1标量替身没有这种内生电网状态，故可直接匹配相同g。

| 评价 | 具体检查 | 输出解释 |
|---|---|---|
| 瞬时MW | q_req=(g+h)/a；逐时检查q_req≤D、q_req≤Σ_{j:a_j=t}f_j A_j/Δt及0≤w−q_req≤K；检查对应即时P和网络/CFE | 只通过当期必要检查；忽略债务、期限和未来恢复 |
| 固定恢复余量 | 以上检查外，预先固定R_fix及η；建立同批次、同期限账本，恢复小时r≤min(R_fix,D)，保持q r=0 | 常数余量近似结果；不把实际未来K、网络、Y的可恢复上限换进R_fix |
| 完整时序 | 同批次账本；逐时实际K、P、网络、Y、共享包络及合同预算；以固定策略执行 | 已验证策略的路径履约、缺口或未决；有独立证书时才给更强可行性结论 |

R_fix的来源与数值在看目标结果前固定；首例取0.2 MW_c作机制假设。简化评价的安排也回放到完整约束上，报告其误判位置。网络状态相同且q_req相同时，改变清洁恢复额度到达时间的匹配对照，才能支持恢复时序归因；若g或即时工作不同，分别报告差异来源。

逐小时至少保存：plan/path/stage、物理小时、K/w/F/X/D、设备/工程状态、P^0/g/h、c_grid/c_cfe/q/r/z、实际P、Y/y、两类承诺缺口、实际CFE缺口、网络检查状态、批次债务与期限、事件预算和信息历史标识。阶段汇总报告即时瓶颈、设备/供电/清洁恢复限制、到期未完成、晚恢复及未知项。费用、经验概率及工程安全性不由首例输出推导。

## 8 实施前检查与来源边界

首例的β、γ、待机、辅助功率、期限、f、η、D及压缩进度均为明确的机制假设，数值见B计划。外生Y必须独立保存；不得从决策后负荷反推。现实应用还需要设备功率曲线、任务期限依据、服务响应合同、清洁归属及实际网络数据。

服务及单位衔接参考[连续服务草案](rq2_continuous_multiday_service_v1.md)和[estimands v4](rq2_joint_deliverability_estimands_v4.md)的具名语义。旧[cfe_preallocation.py](../../src/rq2_joint_deliverability_boundary_v1/cfe_preallocation.py)按y=Rw构造清洁额度，不能直接作为本规格独立Y的实现；[旧双向planner](../../src/rq2_joint_deliverability_boundary_v1/continuous_planner_bidirectional.py)是离线开放终端外松弛，也不能作为固定因果策略的履约证书。

工作包B的最低验证义务为：单位与功率恒等式；逐批工作守恒；未投运资源不可用；跨阶段债务及事件连续；期限小时末结算、晚恢复不擦除逾期；独立承诺与实际CFE分开计量；当前信息相同时动作一致；保存关闭重开与连续执行一致；缺少后续输入诚实终结。具体接口、独立数值核验和完整路径预算按B计划执行。

设计审查是非正式只读核查；实施、冻结及正式运行仍分别遵守[agent.md](../../agent.md)第7–9节。本规格的明确不代表相关接口已实现或现实依据已经补齐。
