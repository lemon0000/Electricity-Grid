# repair-010 joint-AC successor

repair-010 是 repair-009 ifocus4 的新 output-root / 新 preregistration successor；旧 frontier 只作已观测 predecessor evidence，不能被 solver 直接读取，只有经 repair-009 权威 loader 全链审计并原子深复制为 successor-local import 后才能成为 repair-010 输入；旧 attempt 不得 resume。科学协议变更包括：最大可接受 incumbent-relative gap 恢复规格冻结值 `1e-3`，`candidate_frontier_outcomes_observed=true`，joint-AC runtime protocol changed。

worker 保持 fresh isolated process。阶段证据以 `rts_gmlc_joint_ac_phase_event_v1` JSONL 逐条 flush+fsync：`worker_started`、`context_load_started/completed`、`prepared_cases_completed`、`nlp_build_started/completed`、hash-bound `solver_started`、`solver_finished`。binding 覆盖 preregistration/input/frontier/call、candidate/commitment/dispatch、initial strategy、IPOPT options 和 software identity；NLP fingerprints 覆盖 prepared bus/gen/branch/gencost arrays及顺序、controller/reference、chronology/ramp/reserve/initial state、变量/约束表达式与顺序、初值、变量/约束 bounds。

parent 的 startup 与 solver wall 是两个时钟。只有完整验证 `solver_started` 后才建立 `7500 s` solver deadline；此前 timeout、缺事件、乱序或 hash drift 都是 `solver_call_count=0` 的 honest incomplete，绝非 infeasibility evidence。验证后 solver-wall timeout 记为一个已启动但 incomplete 的 solver call，仍不是不可行证据。IPOPT `max_cpu_time=7200 s` 不变。

当前合同有意不可运行：`startup_limit_seconds: null`，因为没有 fresh isolated child 的可审计校准样本；`formal_execution_ready=false`，successor preregistration 也尚未发布。`context_artifact_mode: disabled_unproven` 仅禁止未经证明的 lightweight artifact 路径，并不阻塞已冻结的 `fallback_mode: fresh_rebuild_in_fresh_isolated_worker`。prepare、formal run 与 worker CLI 均在创建子进程前 fail closed；本轮未发布 preregistration、未创建 result root、未启动 solver。

runner 已接入既有 V4 immutable call registration、worker result、checkpoint 与 execution lease 逻辑。formal joint worker 在 repair-010-local executor 中复用 legacy 的 prepared/chronology、result-row、validation、metadata、immutable publication 与 reload helpers，但直接调用 repair-010 专用 adapter 并传入 phase observer；它不再调用会在运行时导入 shared adapter 的 legacy `_execute_joint_call_worker`。每个新 call 另发布 hash-bound phase registration，父进程创建 fresh subprocess 后用实际 spawn PID 校验 journal，分别执行 startup/solver deadline、terminate/kill/grace、worker exit、完整 journal 和 result manifest 校验。任何 `solver_started` 前失败固定为 `solver_call_count=0`，验证后未完成固定为 `solver_call_count=1`；二者均为 honest incomplete，均禁止 resume/retry，均不是 infeasibility evidence。tiny synthetic child integration 只验证 orchestration，不是 formal solver 证据。

repair-010 不继承 repair-004/009 的 attempt recovery。existing worker result、existing checkpoint、最终 `joint_ac` load/merge 的每条接受路径都先重建 successor binding，并要求 immutable phase registration、父进程在 `Popen` 后和轮询前发布的实际 PID spawn receipt、parent-persisted completion receipt、一致且完整的 journal、worker result/native log manifest 和 NLP fingerprints；旧 call/checkpoint 或缺失、乱序、hash drift 的 phase evidence 一律 fail closed，不补造、不重试，也不作为 solver/infeasibility evidence。完整且已结束的 repair-010 checkpoint 可在同一协议内加载，这只是验证完成结果，不放宽 `retry_or_resume_incomplete_call_allowed=false`。若 completion receipt 发布或紧随其后的重验证失败，因父进程已经验证 `solver_started/finished`，固定报告 `solver_call_count=1` 的 honest incomplete 并拒绝 checkpoint；recovery 在 completion 缺失/损坏时只依据 registration + spawn receipt + 可验证 journal 分类，验证到 `solver_started` 才计 1，pre-solver 或坏 journal 计 0，绝不根据 worker result 存在性推断。

父进程最终化采用三个不可变、原子发布的 repair-010-local receipt。完整验证 child result/journal 后先发布 `finalization intent`，绑定 call binding、phase registration、实际 PID spawn receipt、journal hash 与可信 `solver_started/finished`；任何随后 completion publication、重验证、checkpoint 或 success seal **commit 前**失败，先发布 `terminal-incomplete tombstone`，固定 `solver_call_count=1`、`is_infeasibility_evidence=false`、`resume_allowed=false`。只有 completion、checkpoint 和完成事件均成功后才最后发布 success seal，且 seal 绑定 intent/completion/checkpoint manifests。seal publisher 若在 atomic rename 后抛错，父进程必须重验 target manifest 与预计算 exact payload：完整一致即以 committed success 为唯一真值，不得再调用 terminal publisher；target 存在但无法证明 exact commit 时抛 commit-indeterminate 并 fail closed，也不得同时宣称 terminal incomplete。所有 checkpoint、worker-result、load-all、final-result 恢复入口均先检查 terminal（存在但损坏也 fail closed），再要求 valid intent + success seal，最后复验 completion。即使 tombstone 发布失败，已有 intent 且缺 success seal 仍使 completion 永久不可接受，并抛出显式持久化错误；不得声称 tombstone 已落盘。

`import-predecessor-frontier` 先验证源 preregistration/frontier manifest、7 个 candidate、6 个 checkpoint、22 个 nested round manifest、source input contract 与 repair-009 loader 的重构结果，再以 `copy2` 写入临时目录、复核源和副本、生成 `import.json`，最后原子 rename；不使用 hard link，记录 `solver_call_count=0`。`run-joint-ac` 只接受该 successor-local import。当前 readiness gate 会在创建 output root 前阻止 prepare/import/run/worker；本轮只用 tiny synthetic tree 测试发布协议，未把真实 ifocus4 复制到 repair-010 root。

## Startup calibration protocol (V1 incomplete; V2 frozen but not run)

The explicit `calibrate-startup` stage is the only exception to the closed formal-readiness gate. It creates one fresh isolated child under calibration-only table/log roots and never touches the formal result root, call registry, checkpoints, frontier import, or preregistration. The Windows launcher records immutable request/started/PID artifacts plus redirected stdout/stderr and sets `PYTHONDONTWRITEBYTECODE=1`. Existing calibration or launcher state is a no-resume failure.

The supported background entry is `launch-startup-calibration`. It publishes the immutable request before spawning, then binds actual PID and started receipts. The child accepts the frozen launcher root only after those receipts match its actual PID, request/config/runner/contract hashes; a direct `calibrate-startup` invocation refuses any existing launcher state. If PID/started publication fails after spawn, the launcher terminates only that process, escalates to kill, waits for confirmed exit, and publishes an immutable failed receipt. Failure to prove both exit and failed-receipt persistence is an explicit unrecoverable persistence error; the existing launcher root still forbids restart.

Before any observation, the contract freezes one sample, a `21600 s` calibration watchdog, and elapsed time from the parent monotonic reading immediately before `Popen` to the parent's first actual-PID/hash-bound verification of `calibration_pre_solver_stop`. The mechanical candidate limit is `ceil((2 * observed_elapsed_seconds) / 300) * 300` seconds. This is a 100% operational buffer rounded upward to five minutes, not a statistical tail guarantee, and the receipt never edits the formal config automatically.

The start timestamp is taken after opening the worker log and immediately before `Popen`; the stop timestamp is taken immediately after the full journal loader has verified actual PID, binding, phase order, timestamps and expression/solver-input fingerprints. Consequently parent verification time is included, while arbitrary pre-spawn directory/log work is excluded.

The real child performs fresh context construction, case preparation, NLP expression construction, and actual `casadi.nlpsol(..., "ipopt", ...)` construction. The repair-010-only adapter then fingerprints the complete `x0/lbx/ubx/lbg/ubg` call payload and emits `calibration_pre_solver_stop` before invoking the returned solver callable. The shared V4 adapter is restored to its historical authority SHA `cf5cf1e3d133b7e60f63dbb0d072952a9e78de24cd05d0bb740683e8806013b7`; repair-004/009 loaders therefore retain their original input-contract semantics, while repair-010 binds both the historical shared SHA and its dedicated instrumentation SHA. The permitted solver-call count is exactly zero; `solver_started` and any IPOPT evaluation/iteration are forbidden. Registration, actual spawn PID, phase journal, software/input hashes, worker result, completion, and incomplete receipts are immutable and manifest-bound. Any timeout, interruption, drift, or persistence failure is calibration-incomplete with zero solver calls, no infeasibility meaning, and no retry/resume.

Completion and incomplete receipts are atomic alternatives. If completion publication raises after rename, the parent accepts committed completion only after exact payload and manifest reconciliation; an absent target is a pre-commit failure and may publish incomplete. An existing target whose exact commit cannot be proven is commit-indeterminate, forbids incomplete publication, and remains permanently fail-closed. Coexisting completion and incomplete state is always rejected.

The failure occurred while the inherited repair-009→repair-004 loader correctly rejected input-contract drift introduced by repair-010 instrumentation having been placed in the shared V4 adapter; it is not environment failure, solver evidence, or checkpoint corruption.

Calibration V2 uses a new ID and new table/log/launcher roots, preserves the pre-result one-sample rule, `21600 s` watchdog, and `ceil((2 * elapsed) / 300) * 300` formula, and never reuses V1.
